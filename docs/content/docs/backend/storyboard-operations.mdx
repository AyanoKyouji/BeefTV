---
title: 分镜行操作
description: 通过 MCP 或 CLI 追加、修改和删除画布分镜行
---

分镜行操作使用现有 `/api/ops/:op` 接口，由 MCP 和 CLI 共用。先用 `canvas.get` 读取画布版本、脚本节点和分镜行 ID，再提交写入。

| 操作 | 参数 |
| --- | --- |
| `canvas.script.rows.append` | `rows`：追加 1–32 行；行 ID 和镜号由服务端生成 |
| `canvas.script.row.update` | `patches`：1–32 个带 `rowId` 的局部修改 |
| `canvas.script.row.remove` | `rowIds`：删除 1–32 行；剩余镜号重新连续编号 |

三个操作都要求 `canvasId`、`nodeId`、`expectedRevision` 和写入操作 ID。目标节点必须为 `script`；版本过期、未知行或重复行 ID 会拒绝整批写入。用相同操作 ID 与原参数重试会返回原回执，不再次追加。回执包含画布 ID、新版本、节点 ID 和剩余行数。删除行会同时删除关联到该行的连线，保留生成的素材节点；回执列出删除的连线 ID，整轮撤销会一起恢复行与连线。

可修改剧情、台词、时长、景别、机位、镜头运动、图片与视频提示词等创作字段；角色、资产引用和生成产物绑定不在行级写入字段中。修改提示词时会清除该提示词原有的模板变量，避免后续生成仍使用旧模板。

图片的有效输入（优先图片提示词，为空时使用剧情描述）变化时，行编辑会解除原 `imageNodeId` 及该行指向旧图片的输出连线。原图片节点、任务及已交付素材保留；执行中的旧任务仍可交付到原图片节点，但不再作为新版本分镜的当前图片。镜号重排、台词修改或未影响有效输入的剧情修改保留原关联。`canvas.script.row.update` 回执中的 `deletedEdgeIds` 记录实际解除的连线，整轮撤销同时恢复行与连线。

过期的行在画布文档中保留 `imageBindingStale=true`，画布及全屏编辑器显示重新生成提示；重新创建或明确连接图片节点后清除此标记。它不取消原任务，不删除资源，也不是模型提交失败。

图片节点与分镜行的输出归属使用 `canvas.edge.create`，提供 `canvasId`、`fromNodeId`（脚本 ID）、`toNodeId`（图片节点 ID）、`storyboardRowId`（该脚本中的行 ID）及 `expectedRevision`。它在同一事务内登记行的 `imageNodeId`、清除过期标记，并建立带行句柄及 `storyboard-output` 类型的连线；不是把图片反向连入脚本的参考输入。节点必须属于当前画布，已有其他行归属或已有不同图片时拒绝覆盖。重复调用不推进版本，过期版本仍拒绝；操作回执包含真实行/连线改动，整轮撤销一起恢复。这个操作只关联节点，不提交生成或收费请求。

内置助手沿用只读、当前画布、完全访问三档权限。当前画布模式不能写其他画布；分镜改动记入节点摘要并支持整轮撤销。外部客户端沿用自己的审批流程，后端继续检查资源归属、参数、版本及幂等写入。

内置助手接纳新消息时，从已持久化的轮前画布快照向宿主提供 `storyboardContext`：包含快照版本、Script 节点 ID、标题、选中标记及按当时显示顺序排列的 `rowIds`。该字段由 Go 生成并覆盖请求中的同名字段，不扩大操作权限，也不新增索引或数据库表。

普通新消息中的“第二镜”等位置引用，按发送前保存确认、后端接纳该轮时的快照解释；选中节点沿用界面发送时携带的稳定 ID。解析出唯一 Script/Row ID 后，即使模型首次读取前发生重排，也追踪原 ID，并读取当前字段与版本再写入。新一轮会使用新快照，因此重排后重新发送的“第二镜”对应新一轮的第二行。存在同名脚本且选择或明确引用不足以唯一定位时，助手应先澄清；目标删除后不能把补位行当作原目标。

快照投影超过 24 KiB 时整体省略顺序并标记 `complete=false`，避免部分列表被当成完整位置依据；此时相对位置应要求用户明确目标，不得根据后来读到的顺序猜测发送时的位置。行存在性、归属及 CAS 仍由共享操作层执行；模型的自然语言理解与澄清行为需在实际回合中验证。

项目与素材库的常规增删改查继续使用 `beeftv business discover` 返回的业务接口，不需要新增第二套同义操作。资源上传由 CLI 读取本地文件并提交资源接口，后端不接受任意宿主文件路径。

分镜行时长为 1–60 秒；省略时默认 6 秒。行命令与手工界面的 `canvas.document.commit` 在后端共用时长、提示词模板失效、过期图片关联和删除行连线检查。整文档提交若漏清旧模板、过期图片关联、已删除行的连线或未重排镜号会拒绝保存，避免回执确认的内容与提交文档不一致。

`/api/ops` 描述中的 `assistantModes` 和 `replay` 由 Go 操作注册定义生成，官方 Pi 宿主直接使用；缺少分类的工具默认不暴露、不可安全重放。分类只负责发现与重放声明，资源归属、当前画布限制、CAS 和幂等仍由后端执行层校验。外部 MCP/CLI 和手工调用继续使用同一操作入口。
