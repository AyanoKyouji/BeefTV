## 三、T501：执行计划总纲

### 3.1 最终交付目标

在实际 Windows 客户端中完成：

创建项目 → Agent 通过真实文本模型创建三个可操作分镜 → 用户修改第二个分镜 → 立即发出指令 → Agent 读取最新内容并定位正确对象 → 用户确认生成 → 真实图片模型生成 → 图片本地落盘并关联目标分镜 → 退出应用 → 重新启动并离线打开已有成果。

同时完成无需 Agent 的手动真实图片生成、保存与恢复路径。离线能力包括既有项目的基础编辑与素材查看，不要求远程模型在离线时可用。

| M1：Windows 基础应用可运行 | W0 | 基线明确；基础创建、编辑、保存可用；Windows 完整客户端实际启动并进入画布 | 基线记录、构建结果、Windows 实际运行记录、基础持久化结果 |
| M2：Agent 与分镜数据闭环 | W1、W2 | Agent 创建三个真实分镜；用户修改后立即发送，Agent 读取最新已提交内容并正确定位对象 | 稳定对象 ID、编辑前后内容、提交结果与工具读取记录；慢保存和保存失败检查 |

## 四、任务完成与证据口径

任务台账建议使用“待执行、进行中”描述过程，使用第四阶段规定的 Verified / Fixed / Blocked / Failed / Deferred 记录结果。

| 结果 | 判定 |
|---|---|
| Verified | 已有实现通过要求，无需修改 |
| Fixed | 实际缺口完成必要修复，相关验证通过 |
| Blocked | 前置条件或环境阻塞，列明未执行项和恢复条件 |
| Failed | 已执行检查失败，保留结果及后续处置 |
| Deferred | 明确暂缓，说明对当前范围和交付的影响 |

具体未执行检查标记 NOT TESTED。编译通过、静态源码依据、模型自然语言回复、其他平台运行均不能替代相应业务验收。R201～R205 是验证与修复方向，不预设为已证实缺陷。

每项结果记录任务编号、实际基线、发现、必要改动、执行命令与场景、证据位置、回归、未执行项及风险。保护现有工作区、revision、旧项目、费用确认和凭证；任务级 Git 提交按实际授权及仓库规则执行，记录真实 Commit，不预填结果。
