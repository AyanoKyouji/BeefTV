## 一、阶段背景与目标

当前任务是由个人使用 AI 辅助开发，优先评估基于 BeefTV 改造，制作能够体现老板产品构想的 Windows 客户端 Demo。老板以 AI 短剧制作举例，但讨论后将产品方向确定为通用型 AI 媒体创作平台，而非仅服务短剧的固定流程工具。

项目同时存在两类商业可能：软件未来独立发展，以及与公司 GPU 服务器、模型服务组合交付。两者可以兼容，不能因此强制绑定软件与公司算力。

近期节点为 **2026 年 10 月 23 日（周五）的非强制性部门内部验收**。该节点用于展示阶段性进展，不等于完整产品交付期限。

第二阶段的目标是解决第一阶段识别的问题，明确产品方向、交互原则、模型接入与商业边界，并确定 Demo 的验证原则。本阶段不决定具体技术栈、代码模块划分、精确工期和最终开发范围。

## 二、统一产品定义

一款专业用户优先、兼顾普通创作者，以无限画布为主要创作空间、以 AI Agent 为智能协作者，整合多来源 AI 模型，支持从创意构思到成品导出的通用型 Windows AI 媒体创作平台。

产品方向包含以下原则：

- 专业创作能力与简易操作并存，通过逐步展开能力降低使用门槛。
- 创意、剧本、分镜、图片、视频、后期与导出可以衔接，也可以按任务自由组合，不强制依次完成。
- 项目统一组织内容，画布及其他编辑视图共同操作项目中的创作对象。
- 用户可以使用自部署模型、外部服务或公司模型服务。
- 本地优先，基础编辑不强制依赖公司云端；需要远程模型的 AI 功能依赖相应服务。
- 软件具有独立价值，也保留与公司服务器组合销售和交付的可能。

上述内容描述正式产品方向，不能直接视为本次 Demo 必须全部实现的范围。

## 四、九项解决方案

### 4.1 S001：专业用户优先，兼顾普通用户

平台优先满足专业创作者对流程组织、素材管理、参数控制和持续编辑的需要，同时允许普通用户通过自然语言、默认设置和较简单的操作开始创作。

兼顾普通用户不意味着同时开发两套独立产品。应让用户能够从简单任务逐步进入更细的控制，而不要求一开始就掌握全部专业功能。

**后续约束**：第三阶段必须明确 Demo 的主要演示用户与任务；不能将“兼顾普通用户”扩展为本次必须覆盖所有用户层次。

### 4.2 S002：通用型 AI 媒体制作工作台

平台面向多种媒体创作任务，短剧只是应用场景之一。以媒体项目承载创意、文本、分镜、图片、视频及其关联，支持内容在不同环节间继续加工。

完整产品方向可覆盖：创意构思 → 剧本生成 → 分镜设计 → 图片生成 → 视频生成 → 后期处理 → 成品导出。该流程可自由组合，允许用户从已有素材或中间环节开始。

**后续约束**：产品通用性通过对象和能力的可组合性体现；Demo 可以选定一个具体场景验证，避免同时开发多个行业解决方案。

### 4.3 S003：Windows 客户端与算力服务分离，本地优先

Windows 客户端负责主要创作交互、项目组织及本地基础编辑，模型推理可以在本地、用户服务器、第三方服务或公司服务器执行。

本地优先意味着基础创作与已有项目不强制依赖互联网或公司云端，不意味着全部 AI 能力必须离线运行。云端 Agent 或远程生成模型不可用时，相关智能功能可以不可用，但应明确能力边界。

**后续约束**：第四阶段验证 Windows 运行条件、项目持久化和远程服务连接；不得预先把本地优先解释为所有素材只能保存在本机。

### 4.4 S004：开放式模型服务接入与能力管理

采用连接优先的方向，允许接入用户已有模型和多来源模型服务，不把自动部署模型作为本次 Demo 的前置条件。

统一模型能力入口与基础操作，同时保留模型特有能力和高级参数。例如，不同视频模型对参考图、首尾帧的支持可能不同，界面和 Agent 都应依据实际能力工作。

**后续约束**：需要在技术设计中研究能力描述、服务适配及异步任务处理。当前未承诺兼容所有模型、所有协议或所有参数。

### 4.5 S005：内部模型中转服务，混合式模型接入

公司模型中转平台当前默认内部使用，不在本次 Demo 阶段建设完整商业中转业务。

客户端可以通过公司中转服务使用公司提供的能力，也允许直接连接用户自部署模型或其他服务。中转平台不强制接管所有模型请求。

**后续约束**：避免将项目管理、完整创作业务和全部模型连接集中到中转平台；中转服务具体接口及运维方式留待技术调研。

### 4.6 S006：软件独立商业化，模型服务可选

软件商业价值独立于算力服务。即使客户不购买公司服务器、不调用公司模型服务，仅使用自己的 GPU 和模型，也可以购买并使用软件。

软件授权与模型服务分离，软件和公司 GPU 服务器既可独立销售，也可组合交付。产品方向采用本地优先、云端账号按需使用的方式。

以下事项保留为商业决策：一次性授权或订阅、免费版本、专业版与企业版划分、按用户或设备或组织授权、服务器采购附带的软件权益。它们不阻碍 Demo。

### 4.7 S007：核心创作闭环与分级 Demo 验证

Demo 定位为 **产品交互原型 + 关键技术概念验证（PoC）**。既要让人理解产品如何使用，也要验证关键能力真实可用。

优先验证从自然语言创作指令，经真实创作对象和模型调用，直到素材进入项目并可保存恢复的闭环。完整七阶段流程可以作为产品规划展示，本次不要求各阶段全部成熟实现。

本方案确定验证目标和验收原则；具体功能范围在第三阶段确定，结合第四阶段代码调研再校准。

### 4.8 S008：上下文感知、可控执行的协作式 Agent

Agent 是创作协作者，既能理解指令和项目上下文，也能调用平台能力创建或修改真实创作对象。独立聊天窗口能够回答问题，并不足以证明此方案成立。

Agent 与手动操作应尽可能复用相同的平台创作能力，读取用户修改后的对象状态，让 Agent 生成的内容可继续手动编辑。执行范围、可见结果及撤销和恢复问题应纳入后续设计。

云端 Agent 使用哪些项目数据、哪些素材会发送至远程服务，也需要明确。具体权限机制、操作契约和实现方式尚未在本阶段确定。

### 4.9 S009：无限画布为核心的混合式交互

无限画布作为主要创作空间，Agent、节点工作流和时间线分别辅助自然语言协作、复杂生成流程及音视频编排。节点编辑器不是本次 Demo 的强制项。

用户特别关注不同交互方式切换时的连续性：选中的对象、已有内容、修改状态和关联素材应能够延续，避免在不同界面重复输入或维护互不相通的内容。

**后续约束**：项目管理创作内容，画布负责呈现和操作。节点、时间线与画布不能各自成为独立业务数据源；具体视图同步方案留待技术设计。

## 五、S007 的候选功能分级与验收建议

本节保留讨论中的候选清单，供第三阶段取舍，**不是最终开发任务承诺**。

### 5.1 推荐演示链路

以“制作一个 15 秒、包含三个镜头的科幻汽车广告”为示例：

1. 打开 Windows 客户端，创建项目并进入无限画布。
2. 用户向 Agent 输入创作要求，获得简短创意、剧本或分镜内容。
3. Agent 在画布中创建三个真实分镜对象，用户可以查看和修改。
4. 选择一个分镜，调用真实图片生成模型。
5. 图片进入画布，与对应分镜建立关联。
6. 用户手动修改分镜，再要求 Agent 继续操作，Agent 使用修改后的内容。
7. 保存项目，关闭并重新打开，恢复对象、素材引用、关联和布局。

条件允许时继续生成视频；暂时没有可用视频模型时，可导入已有视频并进行预览或基础组织。该示例用于验证通用能力，不将产品限定为汽车广告工具。

### 5.2 P0：核心验证候选项

| 功能 | 候选完成目标 | 主要验证价值 |
|---|---|---|
| Windows 客户端 | 能在 Windows 环境启动运行 | 满足客户端要求 |
| 无限画布 | 对象创建、展示、移动和基本连接 | 验证主要创作空间 |
| 项目管理 | 创建、保存、重新打开 | 验证本地优先与持久化 |
| Agent 对话 | 理解创作指令 | 验证智能交互 |
| Agent 操作画布 | 创建或修改真实对象 | 验证平台操作能力 |
| 基础媒体对象 | 文本、图片及视频素材展示 | 验证媒体创作基础 |
| 真实模型接入 | 至少接通一种图片生成能力 | 验证实际生成 |
| 生成结果关联 | 结果进入项目并关联创作内容 | 验证流程连续性 |

### 5.3 P1：条件允许时增强

真实视频生成、简单时间线、基础视频导出、图片裁剪与缩放、两个模型服务之间切换、工作流展示、Agent 多步骤执行。

是否实现取决于已有能力、可用服务和进度。不要为部署复杂视频模型挤占核心闭环的实现与稳定性验证时间。

### 5.4 P2：本次暂不要求

完整 Photoshop 式图片编辑、完整 Premiere 式剪辑、完整节点工作流系统、企业级团队协作、完整账号系统、订阅充值计费、服务器管理平台、模型自动部署、完整商业中转平台、多 Agent 协作、全部七阶段自动执行。

### 5.5 六项验收建议

| 编号 | 验收方向 | 可观察结果 |
|---|---|---|
| A | 客户端真实可用 | Windows 中启动并操作主要界面和画布 |
| B | 具备实际媒体创作能力 | 能创建、导入和修改真实创作对象 |
| C | Agent 实际操作平台 | 自然语言指令产生真实对象或对象修改 |
| D | 调用真实 AI 模型 | 请求获得真实生成结果，并进入画布或项目 |
| E | 不同交互协作 | 手动修改后，Agent 使用更新内容继续操作 |
| F | 保存与恢复 | 关闭后重新打开，内容、引用、关联和布局恢复 |

候选结果等级：

| 等级 | 判定原则 |
|---|---|
| 基本通过 | P0 核心链路可运行，关键能力得到真实验证 |
| 超出预期 | P0 完成，并实现部分 P1 能力 |
| 部分验证 | 只有部分能力真实可用，明确记录已验证及未完成项 |

功能状态应区分“UI 已实现”“功能可交互”“真实能力已打通”。模拟调用和规划功能应明确标注。单个模型调用成功，也不等于多模型兼容、复杂任务管理等正式产品能力已经得到验证。

## 六、整体方案一致性检查

### 6.1 五项重点检查

| 编号 | 涉及方案 | 潜在问题 | 已形成的处理原则 | 后续验证重点 |
|---|---|---|---|---|
| C001 | S002、S009 | 画布与项目各自维护内容 | 项目管理内容，画布呈现和操作；素材可被多个视图引用，位置和缩放属于视图 | 统一对象标识与引用关系 |
| C002 | S008、S009 | Agent 与手动编辑形成两套机制 | 尽可能复用相同创作能力，共享最新状态 | 撤销、操作记录、覆盖冲突及恢复 |
| C003 | S003、S008、S005 | 本地优先被误解为全部 AI 离线可用 | 基础创作不强制联网，智能能力取决于模型所在位置 | 离线边界和云端数据发送范围 |
| C004 | S004、S005、S008 | 统一体验掩盖模型能力差异 | 统一基础入口，保留特殊能力及高级参数 | 模型能力描述与 Agent 适配 |
| C005 | S002、S003、S004、S005 | 本地素材无法直接被远程模型使用 | 分离素材逻辑归属与物理位置 | 上传下载、结果落地与重复传输 |

检查结论：九项方案不存在需要推翻产品方向的重大原则冲突，但部分兼容性依赖后续的数据、操作及素材管理设计，不能将方向一致视为实现已获验证。

### 6.2 产品职责边界

| 组成 | 主要职责 | 职责边界 |
|---|---|---|
| 媒体项目 | 管理内容、关联及创作组织 | 不执行模型推理 |
| 无限画布 | 展示、组织和操作对象 | 不独立维护全部业务数据 |
| Agent | 理解意图、规划并调用创作能力 | 不绕过统一操作机制直接改数据 |
| 节点工作流 | 组织复杂生成过程 | 不强制承载全部项目管理 |
| 时间线 | 组织和编辑音视频片段 | 不负责模型接入与认证 |
| 模型接入能力 | 连接服务并执行生成请求 | 不管理完整创作业务流程 |
| 公司中转平台 | 管理公司提供的模型服务 | 不强制接管用户自部署模型 |
| 客户端本地存储 | 保存项目、素材及创作信息 | 不默认承担企业级实时协作 |

本表属于产品职责划分，不决定进程、服务、代码包或数据库的拆分方式。

## 八、阶段结论与交接

第二阶段已完成九项问题的方案讨论及整体一致性检查，形成 S001～S009、C001～C005、D001～D006 和三项主要风险记录。

核心结论是：以项目统一组织内容，以无限画布承载主要创作交互，以可操作真实对象的 Agent 提供协作；保持模型来源开放、本地基础创作独立和软件商业价值独立。Demo 优先验证真实创作闭环，不追求七阶段功能的表面完整。

下一阶段为 **第三阶段：Demo 目标与范围确定**，应完成：

1. 将验证目标转化为具体、可观察的能力。
2. 明确必须实现、条件允许时实现和明确不做的范围。
3. 制定可重复执行的验收标准，并注明真实实现或模拟展示。

随后进入第四阶段技术调研与设计，再制定执行计划、开展 AI 辅助开发，最终验证、展示并总结。第三阶段先按产品验证目标确定范围，不直接照搬 BeefTV 的现有功能；技术调研结果再用于校准可行性与实现成本。
