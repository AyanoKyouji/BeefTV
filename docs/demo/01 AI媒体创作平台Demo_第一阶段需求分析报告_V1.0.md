# AI 媒体创作平台 Demo 需求分析与问题识别

**第一阶段报告  V1.0**

日期：2026 年 10 月 19 日
适用对象：项目负责人、产品人员及参与 Demo 开发的研发成员

## 一  阶段结论与报告用途

当前信息足以进入第二阶段的问题分析与解决方案设计，但尚不足以直接形成完整产品的开发范围和验收承诺。后续应围绕一个具体创作场景收敛 Demo，并将尚未确定的商业、交付和技术边界作为显式假设管理。

项目的方向是建设专业、流程化且灵活的 AI 图片与视频创作平台。提高公司算力利用率是项目初衷，但不是每次模型调用必须满足的条件；平台未来存在独立商业化的可能，与服务器业务的协同仍需进一步确认。

### 本阶段成果

本报告归纳项目背景、需求记录与九项核心问题，说明各项未知信息的影响和处理责任，并建立进入后续设计的条件。本阶段不选定客户端框架、模型接入架构、节点编辑器或开源基础项目，也不承诺完整媒体制作链路在近期 Demo 中全部实现。

### 信息口径

“已明确”指讨论中已有明确转述或澄清，不等同于完成正式需求签字。“初步理解”指用户倾向或基于现有信息的判断；“候选方案”指团队提出的实现选择；“待确认”表示尚无结论。报告中的建议、优先级与责任分配均为分析建议。

近期节点为 2026 年 10 月 23 日周五的部门内部展示与验收，非强制交付期限。“至少具备基本功能”尚未转化为可核验标准。

## 二  项目背景与商业目标

### 项目背景

公司主营服务器业务，具有可供模型部署使用的算力资源。部门成员分别使用 AI 独立制作 Demo，以比较方案与效果。BeefTV 被提及为候选基础项目，其具体版本、适配程度与许可条件尚未评估。

| 事项 | 当前认识 | 确定程度 |
| --- | --- | --- |
| 算力利用 | 老板希望通过项目利用公司现有算力，但允许调用不消耗公司算力的模型服务。 | 已明确 |
| 软件业务 | 若平台效果和市场反响较好，老板考虑将软件部门独立为子公司。 | 条件性设想 |
| 服务器销售 | 平台可能帮助销售更多服务器，但尚无明确销售路径与捆绑方案。 | 推测 |
| 软件收费 | 授权、订阅、调用收费、私有化交付及捆绑销售均未选定。 | 待确认 |
| 中转服务 | 由软件部门提出，属于附加方案；不能视为已确定的独立产品。 | 来源已明确 |

### 产品边界的初步理解

媒体创作平台面向创作任务，模型服务提供生成能力，服务器提供运行资源。这三者可以结合销售，也可以分别提供。用户只使用自部署模型时，平台仍可能通过创作流程与操作体验提供价值，但该价值尚需用户验证。

“用户自部署模型”按管理主体定义，指用户自行部署和管理、可被平台访问的模型服务，位置可能在本机、局域网或用户管理的远端服务器。用户购买公司服务器并自行部署模型，仍归入此类。

### 尚不能作为既定事实的内容

Windows 客户端与服务器的交付关系尚未明确。小型主机预装系统和软件的形式只是此前的理解，不能据此锁定设备型号、操作系统安装方式或软硬件一体机方案。平台是否必须登录、联网、订阅或经过中转服务，也没有定论。

## 三  产品需求记录

下表沿用讨论中已出现的 R003—R007 编号。R001、R002 的原始条目未在本次可核对记录中完整呈现，本报告不补造其编号或定义；相关业务方向另列说明。

| 编号 | 需求与边界 | 来源及状态 |
| --- | --- | --- |
| R003 | 连接用户自行部署和管理的模型；可位于本机、局域网或远端。支持哪些接口、是否负责模型部署和启停，待明确。 | 用户澄清<br>方向基本明确 |
| R004 | 支持多来源模型的方向已形成。允许公司部署模型与第三方服务参与；不要求每次调用消耗公司算力。具体模型和接入路径待定。 | 老板约束经转述<br>范围待细化 |
| R005 | Agent 倾向于理解自然语言并调用平台功能完成创作任务。可调用的功能、多步骤任务及执行确认方式待细化。 | 产品人员提出<br>用户倾向性理解 |
| R006 | Agent 空闲时头像静止，思考时播放动画。思考状态的触发与结束条件、失败与执行状态的展示待定义。 | 产品人员提出<br>基本明确 |
| R007 | 创作交互应专业、流程化且灵活；不强制采用节点编辑器。交互形式由后续方案设计确定。 | 老板方向经转述<br>设计开放 |

### 整体业务方向

前序讨论归纳的媒体制作流程为：创意构思 → 剧本生成 → 分镜设计 → 图片生成 → 视频生成 → 后期处理 → 成品导出。该流程表示产品希望覆盖的业务方向，各阶段功能深度及本次 Demo 是否全覆盖均未确定。

### 需求与方案的区分

多来源模型接入属于能力方向，中转平台是实现它的候选方案；流程化属于业务要求，节点编辑器是交互候选方案；Agent 操作平台属于能力方向，具体工具调用和任务组织机制属于技术设计。以上内容应分别评估。

## 四  媒体流程与 Demo 边界

现有流程还不足以直接拆分开发任务。下表仅列出需要细化的内容，供第二阶段收敛场景使用，不代表各环节已纳入近期交付。

| 业务环节 | 需要细化的输入输出与能力 |
| --- | --- |
| 创意与剧本 | 输入是自由描述、已有脚本还是结构化需求；输出是文本建议还是可继续编辑的项目内容。 |
| 分镜设计 | 镜头字段、剧本到镜头的对应关系、人工调整方式，以及人物与场景一致性的要求。 |
| 图片生成 | 文生图或图生图的范围、参考素材、参数配置、结果选择与重新生成方式。 |
| 视频生成 | 文生视频或图生视频的范围、镜头时长、任务状态及失败后的处理方式。 |
| 后期处理 | 是否包含镜头拼接、裁剪、字幕、配音、音乐或时间线编辑；编辑深度尚未定义。 |
| 成品导出 | 输出格式、分辨率、文件位置，以及是否要求单一成片或允许分镜素材导出。 |

### 近期展示的范围管理建议

将周五作为阶段检查点，先确定一个目标用户、一个创作任务和一条可验证的操作路径，再决定所需功能。正式产品的长期方向与 Demo 的演示承诺应分别记录，避免用“基本功能”概括不可核验的范围。

第二阶段应列明哪些功能真实运行、哪些使用预置素材或模拟结果、哪些暂不演示。若使用模拟，展示时需明确标识。模型账号、网络、调用额度和素材准备是否可用，应在确定真实生成范围前核实。

### Agent 能力的验证口径

头像动画只能验证状态反馈，不能证明 Agent 已能操作平台。若后续把 Agent 操作纳入 Demo，应使用可观察的平台变化验证，例如实际创建分镜或提交生成任务；具体示例及范围由下一阶段决定。

### 补充检查项

以下为本轮分析补充的检查项，尚未作为老板或产品人员提出的需求，也暂不新增 P 编号。其目的在于避免进入实现后才发现关键依赖。

模型与环境：可用服务地址、接入协议、访问凭据、调用额度、网络连通性及开发机器配置。

任务与素材：生成耗时与失败反馈、结果保存、重新生成、项目恢复，以及源素材和生成结果的关联。

数据与使用约束：素材是否允许发往外部服务、凭据如何保管、生成内容的使用要求，以及候选开源项目许可是否适合预期用途。具体适用性需后续核查。

验证与完成度：核心路径如何演示，哪些结果必须真实生成，遇到网络或服务故障如何说明，以及本轮 Demo 能验证哪些假设。

## 七  阶段结论与后续工作

### 第一阶段的完成判断

已形成项目背景、需求口径、九项核心问题及依赖关系，可以进入第二阶段。当前成果是需求分析基线，不是正式产品全部需求已确认，也不是周五展示范围已冻结。

需继续保留的边界包括：算力利用不是硬性约束；中转平台不是已确定的独立产品；节点编辑器不是强制要求；Agent 操作平台是倾向性方向；子公司计划取决于平台表现；软硬件捆绑及收费方式尚未确定。

### 第二阶段建议产出

第一，围绕目标场景提出有限的产品方案，比较 Windows 客户端的必要性、客户端与服务端的职责，以及项目数据与生成素材的位置。

第二，分析自部署模型、公司模型与第三方服务的接入关系，说明是否需要中转层及其最小职责，避免直接扩展为完整模型服务产品。

第三，细化 Agent 与平台操作的关系，比较分步骤、节点或混合交互，并核实 BeefTV 是否适合作为基础。评估需覆盖能力适配、改造成本、维护状况及许可条件；本报告不预判结论。
