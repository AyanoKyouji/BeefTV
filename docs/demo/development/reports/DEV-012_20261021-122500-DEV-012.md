## 验证目标

核对手动入口与 Agent 入口到共享素材交付层的行为一致，并确认无分镜目标的独立手动生成可以作为项目素材保存而不强制挂到任意分镜。

## 代码层汇合点（静态核对）

- 手动入口：用户点击图片节点"生成"按钮 → `executeImageGeneration` → `runCanvasGenerationTaskToConsumer` → `runBackendCanvasGenerationTask`。
- Agent 入口：`executeAssistantProposal` → `generate(nodeId, kind, prompt)` → 同一个 `handleGenerateNode` → `executeImageGeneration`。
- 共享交付层：后端 Go Task 落盘 → Asset 登记（`materializedAssetId`）→ 前端 `applyMaterializedGenerationTaskResultToNodes` → `buildGenerationTaskNodeResult` → `uploadImage`（本地资源库）→ `assetId` 写入节点 metadata。
- 分镜目标绑定：`reconcileStoryboardTargetConnections` / `reconcileStoryboardRowOutputs`；只在有分镜上下文时触发。
- 无分镜目标：`assetId` 无条件写入节点，`reconcileStoryboard*` 不触发；独立节点不会被强制挂到任何行。

## 受控运行方法

完整复制 DEV-009 已生成的真实 JPEG 字节（SHA-256 `8bfba550…a984b4a`），通过本地 `openai-image` 回放端点返回。图片模型 `dev012-replay-image` 指向本地回放；文本模型保留 `deepseek-flash` 真实配置。每个场景使用独立画布。

| 场景 | 入口 | 分镜目标 | 交付结果 |
| --- | --- | --- | --- |
| A `manual-target` | 手动 | 有（Row `…-row-a`） | 通过 |
| B `agent-target` | Agent | 有（Row `…-row-a`） | 通过 |
| C `manual-standalone` | 手动 | 无 | 通过 |

三个场景共用同一份回放图片字节；三个 Task 独立，三个 Asset 独立，三个 storageKey 独立。

## 恢复验证

完全退出 Go / Vite / Node 宿主后重启（同一隔离数据目录 `.local/project-workbench-debug/dev012`），三个画布 revision 分别保持 7 / 6 / 5；Task ID、Asset ID、storageKey、Row `imageNodeId`、`storyboard-output` 连线和文件 SHA-256 全部一致；场景 C 画布仍然没有 script 节点和分镜连线。

## 模型调用统计

- 图片：0 次远程调用（3 次本地回放 POST，均返回复用的真实 JPEG 字节）。
- 文本：1 次 DeepSeek `deepseek-flash` dispatch（场景 B 的 Agent 提案回合）。

## 边界与保留

- 本轮验证的是两条入口的共享交付管线一致性，不是 Agent 自主从空白创建分镜并生成图片的完整闭环（后者 DEV-009 已 Verified）。
- 不把受控图片回放当作新的真实图片生成验证；三次交付的文件都是复用的 DEV-009 真实产物字节。
- 完整 AT008、W4、M3 与最终 Windows 验收保留；交付中断矩阵（DEV-015）保留。
- Mac 上验证；Windows 阶段回归保留。

## 结论

两条入口在同一个共享交付层产出结构一致的交付结果：Task 成功、Asset 登记、storageKey 指向独立文件、`assetId` 写入节点、文件哈希与源字节一致、冷启动后完整恢复。有分镜目标时，两条入口遵守同一关联规则（Row `imageNodeId` + `storyboard-output` 连线）；无分镜目标时，独立手动图片作为项目素材保存，未被强制挂到任何分镜。
