## 1. 已复现的问题与修复

基线只有选中节点 ID，没有指令发出时的分镜顺序。用户要求修改选中 Script 的第二镜，在模型首个真实 `canvas.get` 到达但尚未处理时，通过分镜编辑界面把原第二镜移到第三行。释放读取后，模型修改了补位到第二行的另一镜；工具回执与业务文档均证实误改，不能仅凭模型声称“第 2 镜已完成”判为通过。

修复复用 `BeginAssistantTurn` 已持久化的轮前文档，派生 `storyboardContext`，包含版本、Script ID、标题、选中标记及按发送时顺序排列的 Row ID。Go 覆盖请求中的同名字段；从确切轮前快照读取，避免较早的归属检查与正式接纳之间再次读取造成版本混淆。没有新增索引、表或持久化体系。

宿主将该结构提供给模型，并要求先解析唯一 Script/Row ID，再读取当前字段和版本、按原 ID 操作。重排、版本变化不能改绑；目标删除时停止该项操作；选择及引用不足以唯一定位时先澄清。共享操作层原有行存在性、归属、CAS、幂等和权限校验保留。

快照投影超过 24 KiB 时整体省略顺序、返回 `complete=false`，不能把部分列表作为位置依据。该边界由专项测试覆盖，没有为验证大快照再消耗真实模型请求。

## 2. 位置语义

普通新消息的“第二镜”按发送前保存确认、Go 正式接纳该轮时的分镜快照解释；选中节点使用界面发送时携带的稳定 ID。点击后若仍处于保存/助手准备过程，尚未接纳的内容不被描述为已发送。目标解析后追踪 Row ID；新一轮使用新快照，重排后重新发出的“第二镜”可以指向另一行，不把位置永久绑定到历史目标。

本次使用 Script 级选择及明确 Script/Row ID 引用，没有新增分镜行选择控件。运行中补充指令的相对位置解析未单独实测，不扩大为所有自然语言或所有后续生成情形的保证。
