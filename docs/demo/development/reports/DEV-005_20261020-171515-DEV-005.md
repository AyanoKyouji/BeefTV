## 1. 问题与修复

旧发送路径等待模型配置保存，但没有等待画布提交。基线复现中，将一次真实文档提交保持未完成，再立即发送；聊天请求先于保存确认发出，此时业务读取仍为旧提示词。该聊天请求在浏览器测试层被明确拒绝，没有调用模型，避免为复现生成无效付费回合。

修复复用现有编辑器、保存队列及业务文档，没有新增数据源或固定等待时间：

- `use-canvas-project-lifecycle.ts` 提供发送前保存方法，从实时编辑引用写入现有 store，等待本机缓存和后端确认；保存期间有新编辑时继续提交至确认。异步过程检查账号、画布归属及取消信号，保存错误向调用方抛出。
- `local-workspace-repository.ts` 的显式提交清除同画布待触发的防抖计时器，继续使用现有串行队列及 revision 校验，避免把尚未执行的计时器当作保存完成。
- `project.tsx` 将该方法接入 `use-canvas-assistant.ts`。新消息在模型配置、助手就绪、会话准备完成后，紧邻实际聊天请求之前等待画布保存；运行中补充要求也走同一等待边界。
- 保存失败时不发聊天/补充请求；新消息明确提示“消息未发送”，补充消息区分“保存失败未发送”和“已发送但回执不确定”。本地编辑及未发送内容仍可核对、保存和重试。

新增六个真实 hook 浏览器测试，覆盖等待、保存失败、停止、账号切换、补充失败及助手就绪等待后的最终保存位置；同步更新一条已有源码接线断言，并补充公开功能说明。Go 生产接口、数据库、权限及写入 CAS 未改动。
