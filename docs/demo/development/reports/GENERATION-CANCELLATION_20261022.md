# 生成期间取消入口与回执竞态修复

- 日期：2026-10-22（Asia/Shanghai）。
- 源码：`5eac6ba`，补充旧节点处理 `592b802`、`c3e1ff2`。
- 用户现象：刚点击生成后发现提示词需要修改，但输入区按钮禁用，画布中也没有可用的取消入口。

## 原因与处理

输入区原来在 isRunning 时直接禁用生成按钮，只显示旋转图标。节点内的取消操作又只在有 taskId 时出现，页面取消 handler 没有 taskId 就直接返回，因此准备素材和等待任务创建回执都存在操作空档。

现在输入区在生成期间显示可点击的方形“取消生成”按钮，清空/修改提示词不影响取消；展开编辑器共用这一行为。取消处理中显示“正在取消生成”并防止重复点击。加载中的节点在尚无 taskId 时也显示取消入口。

取消通过独立的用户意图标记中止当前请求流程：准备阶段停止后不创建 Task；创建请求已经发出时保留原请求，收到迟到的 Task 回执后调用原任务的取消 API。取消失败则读取原 Task，保留运行状态和身份并报告未确认；完成先于取消时保留成功回执。没有增加上游生成、重试或猜测的供应商取消接口。取消操作沿用捕获的用户 scope；关闭页面和切换用户的普通 abort 仍只脱离观察，不取消持久任务。

旧的“提交中”/“待确认”空节点如果查不到 Task，则停止本地转圈并显示“提交结果待确认”，保留原 operation ID 和编辑稿。此处理只在身份仍匹配、尚未绑定真实 Task 时应用，不覆盖迟到的新绑定，也不把未查到回执伪造为取消成功。之后仍须查询原提交，不能直接重交。

## 上游与费用边界

`POST /tasks/:id/cancel` 停止的是本地任务。现有后端只对已支持的供应商协议尝试撤销并核对；当前用户提供的 Predictions 文档没有任务撤销合同，H3 新协议不编造取消地址。界面提示：已被上游受理的请求仍可能继续生成和计费，不保证退款。用户可先编辑当前提示词，原任务已确定停止或结束后再发起新生成。
