## 发现与修复

1. **明确参数拒绝被误判为结果未知。** 本机返回 HTTP 400、结构化 `invalid_request / invalid_request_error`，诊断正确记录状态与参数，但路由未把它认作明确拒绝，最终显示 `submission_unknown / submission_uncertain`。修复只接受 HTTP 400/422、结构化参数分类且没有上游 Task ID 的拒绝证据，并把该证据传入路由层。裸状态码、仅文字、普通 5xx、带原任务 ID 或包在先前未知状态内的错误，不因此解锁。
2. **已受理图片的查询超时丢失未知状态。** 第一次真实等待约 45 秒后，原任务 ID 已保存，但 worker 将类型化超时改写为“图片生成等待超时，请稍后重试”，API 没有稳定错误码，页面未说明结果未知。底层重试验证仍拒绝已受理任务，未实际重付。修复在已存在上游 ID 的 `canvas_image` 超时时保留原 ID 和类型化原因，进入 `submission_unknown / submission_uncertain`，不再提示盲目重新提交。

同时补充 503 的可见说明：有正式 `upstream_http / HTTP 503` 诊断且结果未知时，显示“模型服务暂时不可用，提交结果尚未确认”，继续显示查询原任务的建议并隐藏重新生成操作。没有直接展示供应商原始正文。

503 本身不能证明上游未创建任务，因此本轮保留未知状态和原任务重试保护；没有为了显示“服务不可用”而把普通 503 当成可安全重发。未更改默认 45 秒查询超时、任务执行循环、付费确认或凭证保存方式。
