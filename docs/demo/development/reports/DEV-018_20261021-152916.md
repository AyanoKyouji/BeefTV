## 集成缺陷与修复

首次完整流程暴露：Agent 可以创建图片节点和提出生成方案，但 `canvas.edge.create` 原来只能建立普通参考连线，无法登记分镜行输出归属。模型尝试图片→脚本的反向连线被拒绝；不能将普通连接或聊天说明视为已经绑定。

复用现有操作，新增可选 `storyboardRowId`，按脚本→图片方向原子写入 `row.imageNodeId` 和包含 `storyboardRowId`、`fromHandleId=row:<id>`、`relation=storyboard-output` 的正式连接。窄领域端口校验用户、画布、脚本、行、图片类型与当前 revision；禁止抢占另一行的图片或静默替换已有输出。重复调用不推进版本，旧版本拒绝；正式回执记录脚本变更，使整轮撤销同时恢复行与连线。

未增加另一套 Agent 运行时、模型协议、生成循环或绕过审批的路径。工具合同、实现、调用方、测试夹具及后端专题文档同步更新。修复归属 DEV-009/011/012 的自主分镜关联集成缺口。

## 两轮实际操作

每轮从空数据库创建项目，仅复制本机已有加密模型配置。没有通过 API 预置分镜、图片、提案或成功结果。

1. UI 新建项目；真实 DeepSeek 通过正式工具创建一个脚本和三条 5 秒分镜，填写画面、旁白、景别、图片及运动提示词。
2. 在分镜全屏编辑器修改第二镜图片提示词，关闭编辑器后立即发送；第一轮编辑填完至点击发送为 130 ms，第二轮 119 ms。没有在编辑与发送间插入固定等待或读取 API。
3. 正式工具结果包含稳定 Row ID 与最新提示词；Agent 创建图片节点、登记行输出并提出单图方案。两轮节点提示词和最终任务 prompt 均逐字等于手工输入。
4. UI 点击提案“生成”；每轮仅一个任务、一个真实图片 POST、一个成功路由及一张实际图片，任务最终 `succeeded / READY`，节点、Asset、Resource 与本地文件对应。
5. 保存后退出本轮 Go、Vite 和宿主，使用禁止外网、允许 localhost 的进程环境重启，以全新浏览器资料读取。外网连接探针被操作系统拒绝；完整文档深比较、行与连线、历史轮次及实际图片字节哈希一致，恢复阶段零聊天/图片请求。

实际生成指令为：

> 请根据当前选中的分镜脚本的第二个镜头生成一张参考图片：先读取它最新保存的图片提示词，将原文用作新图片节点提示词，把图片节点关联到这个镜头，再提出默认图片模型的生成提案。只处理这一镜，不修改分镜内容，不生成视频，等我确认后再生成图片。

指令没有重复新画面描述或注入 Row ID。当前发送合同传递所选 Script ID，镜头通过“第二个”及轮前顺序定位；**本轮没有证明仅凭表格行勾选、完全省略镜头位置也能识别目标**。此处是 T504 示例措辞的明确化，不能扩大为任意隐含行选择已验证；跨行/重排泛化仍参照 DEV-006/009。

第一轮新提示词为“深蓝色雨夜路口，银色概念汽车左侧低机位构图，左前轮有一小片红色霓虹反光，青绿色玻璃建筑倒影，真实摄影，无文字无商标，正方形构图。”第二轮改为白色汽车、雪山弯道、绿色极光、橙色反光路牌和斜俯拍；具体原文保存在 `edited-input.json`。
