# Mac 原生 Agent 读取画布失败修复

- 日期：2026-10-21（Asia/Shanghai）。
- 修复提交：`3e5b44f`，开发分支 `demo/ai-media`。
- 当前安装构建：`de2c10b`，v1.7.26，darwin/arm64。
- 用户现象：在空白画布输入“随机生成图片”，出现“没能读取对话”和“对话还没读回来”，没有进入生成阶段。

## 原因与修复

这是工作区初始化顺序缺陷。`startApplication` 在确认当前后端工作区身份之前，按 WebView 上次使用的 scope 水合缓存、读入后端画布并写入版本日记。切换原生验证目录和日常目录时，验证库的画布及确认版本可能因此写进日常缓存。再次打开日常目录，界面能显示缓存，但当前 SQLite 没有对应画布，读取历史和 `canvas.document.commit` 都返回 404。

原生日志、两个数据目录的只读数据库查询及 WebKit 缓存记录相互印证了这一情况。它与模型供应商、图片模型和余额无关；失败发生在任何模型请求之前。此前基础原生验证覆盖了 API 保存和恢复，没有覆盖切换数据目录的完整前端启动流程。

现在由工作区初始化器先选择后端返回的 scope，再完成该 scope 的缓存水合，最后读入后端画布和确认版本。启动入口不再提前投影画布。另将 Agent 发送前的保存屏障提前到历史读取和会话创建之前，同时保留实际派发前的再次保存，避免等待宿主或会话期间出现的新编辑遗漏。保存失败、取消或 scope 变化仍阻止派发；没有把真实读取失败转换为空历史，也没有放松归属校验或自动重建已删除画布。

## 当前画布恢复

先备份日常 SQLite，保留当前 scope 的完整画布缓存，再经正式本机 PUT/CAS 接口恢复受影响画布。当前缓存含一个尚未生成的图片占位节点，恢复保留它及全部图结构；没有复制已经删除的测试画布，没有修改模型配置或直接写业务表。

原生后端随后确认画布 revision 3、节点和连线与缓存一致。通过正式 owner 引导签发短期 UI 会话，`assistant/sessions` 和 `assistant/history` 均成功，历史为零回合。首次辅助检查缺少 UI 会话返回 403，补齐正式凭据后通过；这不是再次出现画布 404。
