# 图片配置缺失字段导致页面异常：修复记录

- 起始提交：`314a1c0`；分支：`demo/ai-media`。
- 结果：**Fixed（Mac）**。
- 用户发现：DEV-007 过程中曾显示“页面异常”，要求修复后再推进下一项。

## 原因与此前处理的区别

这是一个配置健壮性缺陷。DEV-007 手写图片能力配置遗漏了 `quality.values` 等字段；`normalizeModelCapabilityConfig` 对持久化 JSON 直接调用 `.map()`，图片设置和能力编辑器会抛出 TypeError，进入路由异常页。此前只是补全测试配置，使生成验证继续成功，**没有修复产品对缺失字段的处理**。

用户本次附带的同名 `prepare-failure.png` 已是正常空图片节点。旧测试脚本在后续失败尝试中覆盖了同名截图，不能再把该文件当作首次异常的原图。本次用独立 run-id 记录基线和修复后的结果，未改写 DEV-007 历史截图。

## 修复

图片能力在进入 UI 前合并所选协议和模型的默认字段，再规范化数组。缺失或无效数组不再直接调用 `.map()`；已配置的 `false`、`0`、空数组、单张限制及尺寸限制保留，原始配置对象不被修改。图片能力编辑器也使用相同入口，并传入对应协议的默认值。

没有改为吞掉渲染异常，也没有删除已有的错误页。此次没有修改供应商适配器、密钥、数据库结构或生成次数。

## 验证

| 检查 | 结果 |
| --- | --- |
| 原代码回归用例 | 5 项中 4 FAIL、1 PASS；缺少 quality/size 数组的真实 JSON 形状复现 TypeError |
| 修复后专项及相邻回归 | 63 PASS、0 FAIL，包括新增 5 项；检查设置和能力编辑器、协议默认值、空/无效列表、明确限制和不修改输入 |
| 前端构建 | `bun run build` PASS，包含 TypeScript 检查；已有大 chunk 提示保留 |
| 真实浏览器基线 | 经 Vite 加载起始提交的能力模块，工作区配置响应仅删除 version/quality.values，图片交互后出现“当前页面没有正常加载 / reading map” |
| 修复后浏览器 | 同一缺失字段响应，深色和浅色主题均能打开画布及图像设置，无路由异常或 pageerror |
| 模型费用 | 所有任务 POST 和助手聊天均设拦截保护，实际拦截计数也为 0；没有新增模型调用 |

浏览器使用 DEV-007 数据库及图片的独立副本。新手引导等待、菜单标题定位和资源副本准备曾使测试控制器失败，已根据页面和源码修正；这些失败不作为产品验证通过的依据。最终基线/深色/浅色三场景分别保存截图及结构化结果。
