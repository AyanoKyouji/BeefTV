# 画布图片生成视频的中转接入修复

- 日期：2026-10-21（Asia/Shanghai）。
- 修复/安装基线：`4e8ec77`，v1.7.26，darwin/arm64。
- 用户现象：从画布现有图片生成视频，出现“填写参考素材链接”，要求 HTTPS 地址或对象存储。
- 结果：新协议、自动上传及 Mac 客户端更新完成；已核实真实免费上传和公开读取，未提交收费视频生成任务。

## 原因

弹窗发生在视频提交前。现有 URL-only 预检查只能采用可访问链接或对象存储，未接入该中转的 `/api/v1/files`，本机 `resource:` 图片因此被阻止。

同时，客户端 H3 系列配置选择了 `minimax-video`。该协议与用户提供的 Predictions 包装入口、参数、响应不一致。仅上传图片仍不足以解决后续调用，不能据此判定模型不可用。

本轮使用已保存凭据只读查询三个模型的 `/api/v1/models/{id}`。真实 schema 确认：基本 H3 分辨率为 768P/2K/4K，Max/Max Turbo 为 480P/768P/1080P；均为 5～15 秒。Turbo 只支持首尾帧，没有图片/视频/音频参考数组。原生 MiniMax 默认的 4 秒、水印及部分分辨率不能直接照搬。

## 处理

新增声明式插件 `predictions-h3-video`，创建 `POST /api/v1/predictions`、查询 `GET /api/v1/predictions/{task_id}`，使用 `{model,input}`、`data.task_id/status/outputs`，非零 code 按失败处理。创建携带宿主稳定幂等键，查询间隔 3 秒；首尾帧、参考数组、Turbo、分辨率和互斥参数分别映射与校验。

只有明确选择该协议时，任务执行器才读取当前用户有权限的本地资源，使用同渠道凭据和既有出站传输上传 `files` multipart，取得 `data.list[0].url` 后继续生成。传输层保留取消、诊断、凭据和网络策略。原画布资源不删除；执行参数不再携带本地引用/base64。上传失败保留“尚未提交生成”的边界，不会进入视频创建，也不把它误记为结果未知而自动重新生成。

前后端能力默认值同步。原有其他渠道的链接弹窗、对象存储和 HTTPS 规则保留。完整接入说明见[中转平台图生视频接入](../中转平台图生视频接入.md)。
