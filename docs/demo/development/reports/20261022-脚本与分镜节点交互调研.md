# YUNTV 脚本与分镜节点交互调研

调研日期：2026-10-22。性质：交互设计建议，尚未实现。

## 结论

建议把当前“脚本节点”重新组织为可展开的“分镜板”：画布中显示镜头缩略图、顺序和进度；展开后编辑镜头与执行生成；表格保留为批量编辑视图。

选择这个方向的原因是，用户当前真正需要回答的是“这一镜拍什么、参考谁、出了什么图、能否生成视频、下一步做什么”。现有节点优先显示长提示词和字段，主要命令放在更多菜单中，产物又分散到画布其他节点，用户很难直接回答这些问题。

这个建议保留最初约定的无限画布、手动创作与 Agent 共用对象、素材关联及持久化能力。它调整编辑与反馈方式，不要求先建设专业多轨剪辑系统。完整自动成片属于更大的能力范围，不应成为本轮改善的前置条件。

## 调研方式与边界

- 阅读官方产品文档、帮助中心和更新说明，并对照本地当前源码及用户提供的实际使用现象。
- 没有登录竞品账户、执行竞品付费生成或开展用户可用性测试；下文“适合借鉴”是基于资料和本项目任务的判断，不是实测排名。
- 没有调用真实模型，没有上传项目素材，没有修改客户端。

## YUNTV 当前交互的具体问题

以下来自本地 `web/src/components/canvas/canvas-script-node.tsx`，不是对远端版本的推测：

1. **默认优先展示模型提示词。** 紧凑视图固定展示序号、时长、视频提示词、台词与关联资产。故事内容、图片提示词和实际产物不在同一处清晰呈现。
2. **流程外观与点击行为不一致。** 顶部“分镜 / 分镜图 / 视频 / 合并成片”使用展示性元素，容易被理解为可点击步骤。
3. **主要操作藏在更多菜单。** 生成未完成分镜图、生成未完成视频和合并视频都在该菜单中，用户必须先发现入口。
4. **输入参考与输出产物的名称不清楚。** “关联资产”显示镜头的参考绑定；生成图片、视频另有 `imageNodeId` / `videoNodeId`。界面显示“未关联”时，用户不容易判断究竟缺参考还是缺生成结果。
5. **画布节点与镜头进度分离。** 新图片、视频可以成为独立节点，但用户需要在节点之间来回定位才能理解一镜的完整状态。

保存同步、协议适配及任务取消属于另外的可靠性问题。改善布局需要使用这些能力，但布局变化不能替代相关缺陷修复。

## 建议的信息结构

区分四种内容，并让用户看清它们如何关联：

- **故事/原始脚本**：用户想表达的剧情及总体要求。
- **镜头**：顺序、画面、动作、台词、计划时长与参考素材。
- **生成设置**：图片/视频提示词、模型、比例、生成时长等。
- **成片顺序**：采用哪些镜头视频、如何排序与截取。

图片与视频提示词由镜头内容辅助形成，允许展开修改；不能让用户必须先理解模型参数才能写镜头。Agent 修改与手动修改始终落在同一份镜头对象上。

### 画布层与编辑层

- 画布节点保持紧凑，呈现标题、镜头数量、代表缩略图、完成数量和“打开分镜板”入口。
- 用户点击明确的打开按钮进入较大编辑区域，避免在缩放后的画布节点里编辑大量长文本；不能只提供双击入口。
- 图片、视频节点可继续作为画布可复用对象；卡片和节点引用同一素材，不创建两套内容。提供“在画布中定位”。
- 表格用于批量改时长、台词或提示词，可切回卡片；同一镜头不能因切视图、改顺序或移动节点而丢失身份。

### 常用操作与状态

- 主工具栏常驻；顶部若保留流程步骤，应能切换到对应内容，并显示“图片 2/3”这样的数量。
- 每镜分别显示图片状态和视频状态，不用一个笼统红点涵盖全部任务。
- 状态至少区分未生成、等待前置结果、排队、生成中、完成、失败、已停止、内容已变更。
- 失败在镜头旁说明原因和下一步；只有图片失败就重做该图，避免默认重跑整组。
- 重做保留旧结果和版本选择；修改后提示哪些下游结果需要更新，不立即删除可用素材。
- 取消本地等待与上游已确认取消必须分别呈现。上游仍可能执行时，允许用户明确发起新任务，同时保留原任务查询入口，不能宣称已经停止计费。

### 生成流程与模型限制

默认“分镜成片”流程建议为：故事 → 镜头 → 可选分镜图 → 每镜视频 → 按镜头顺序合并。另设“多图参考生成单条视频”，明确其输出是一条模型视频，不等同于逐镜剪辑成片。

显示文本、图片、视频三种模型各自用于什么；模型不支持参考图时，在提交前指出。参考图默认自动上传到已配置的渠道，只有缺少能力或配置时才让用户处理链接。

将“计划剪辑时长”与“模型生成时长”分开：例如计划镜头 3 秒而模型最低生成 5 秒，应显示限制和可选处理方式；不能静默改时长，也不能等任务提交后才告知。

### Agent 与手动操作

按用户已表达的偏好，明确要求执行的 Agent 指令可以直接运行，并显示执行清单和当前步骤，不必逐张确认。若指令只要求提方案，则停留在规划。

“先角色图 → 再分镜 → 再分镜图 → 最后视频”的顺序应作为实际依赖执行；前置任务未成功不能假装后续已完成。用户可以暂停、修改尚未提交的内容，再从适当位置继续。实际并行范围仍受指令要求和素材依赖约束。

只移动节点位置不应使内容生成计划失效；提示词、参考素材或目标镜头改变时，才重新检查受影响步骤。预算不可获得时显示未知，不编造费用；自动重试收费任务需区分同一任务查询与创建新任务。

## 建议实施顺序与验收

**第一轮：优先解决可发现性。** 常驻生成入口、默认分镜卡片、逐镜图/视频状态、参考输入与生成结果分开、明确的详情入口。继续使用现有任务及对象体系。

**第二轮：改善完整创作过程。** 原始脚本与镜头编辑分开，加入统一参考区、批量设置、版本选择和失效结果提示。

**后续再评估：** 更完整的剪辑、音频、转场和时间线。是否建设取决于 Demo 展示与实际使用需求，不把成熟竞品的全部模块复制进来。

第一轮可用以下任务验收，不以“界面更漂亮”作为唯一标准：

1. 首次使用者写一句故事，能发现拆分镜头入口，随后直接发现生成图片与视频入口。
2. 三个镜头的参考、当前图片、视频与下一步操作都能在分镜板内找到，无需猜测“未关联”的含义。
3. 第二镜失败时能只重做第二镜；其他成功产物、顺序和关联保持正确。
4. 移动节点或重排镜头后，Agent 和手动编辑仍操作原镜头及正确素材。
5. 取消后能继续编辑并清楚选择继续查询原任务或提交新任务；界面如实说明上游状态。
6. 模型能力、参考格式和时长不匹配在收费提交前被发现；保存失败时保留草稿并提供就地处理入口。
7. 关闭重开后，镜头、素材版本、任务状态和编辑内容恢复一致。

## 与原 Demo 目标的关系

原第三阶段报告的核心是画布真实对象、Agent 与人工共用最新内容、生成素材关联及保存恢复；专业多轨剪辑不在基础范围。本建议以“分镜板”改善这些现有对象的操作方式，继续保留画布作为工作台。参考：`docs/demo/03 AI媒体创作平台Demo_第三阶段目标范围与验收报告_V1.0.md`。

总体建议是先做一版三镜头可完整操作的分镜板，再通过实际使用决定更复杂的字段和时间线。本文不代表已批准或完成界面改造。
