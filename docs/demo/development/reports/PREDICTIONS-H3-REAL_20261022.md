# Predictions H3 真实图生视频验证

- 日期：2026-10-22（Asia/Shanghai）。
- 原生程序：v1.7.26，darwin/arm64，包含修复 `4e8ec77`；本轮未修改程序代码或重新构建。
- 结果：真实 MiniMax H3 的本地参考图上传、视频创建/查询、本地资源交付、画布绑定及原生播放器显示通过。
- 费用：只创建 1 个真实视频 Task、执行 1 次；中转回执实际扣费 **0.30 USD**。没有使用 Seedance 或 Seedream。

## 范围与过程

沿用已安装的客户端和已保存的中转配置。原生界面打开用户现有画布，原图片节点的资源仍是本机 `resource:` 引用。通过界面新增视频节点，再用正式操作 API、当前画布 revision 配置提示词、5 秒、768P、自适应比例，并连接原图片；不手填在线链接，不配置对象存储。

通过原生生成按钮提交一次，未出现“填写参考素材链接”。平台接收任务，后端继续查询同一编号，没有再次点击生成或更换幂等身份。平台返回 success 后，BeefTV Task 达到 succeeded / READY / 100%，产物保存为本地 ready 视频资源，并绑定到新增节点。

原生画布出现视频静态预览及播放按钮；点击后出现 Video Player，截图观察到生成视频画面。该观察只证明播放器能呈现视频，不作为全片动作质量、对白、声音内容或人物一致性验收。

本轮 ffprobe 命令请求了帧计数，但返回未包含帧数，所以只记录媒体元数据读取通过，不将其写成完整逐帧解码。实际平台仍返回 AAC 音轨；当前 H3 schema 没有声明声音关闭参数，不能把节点的“声音关闭”草稿理解为已证实输出无音轨。自适应请求实际输出横幅，也不据此承诺保留原图的竖幅比例。

## 原有空节点与验证边界

原来的视频空节点带有旧提交身份和“提交结果待确认”状态，但后台没有对应视频任务。保留该节点及身份，没有把“未查到”当成可以重交同一未知请求的依据；这次真实测试使用单独的新节点。旧空节点仍可能显示生成中/待确认，本报告不将其记为新的后台运行任务，也不声称已修复旧状态的通用恢复问题。用户可在同一画布的新视频节点查看本次成功结果。

准备阶段，第一次测试草稿的保护性断言发现旧节点的状态字段在页面恢复期间变化，检查后确认图片及业务内容未被改动。该草稿未提交 Task，已用正式操作 API 清理；第二个草稿完成上述唯一收费生成。原生坐标输入曾返回 noWindowsAvailable，后续使用可用的无障碍操作完成新增、提交和播放。准备失败不计为模型生成失败，不隐藏这些中间记录。

本次只验证基础 H3、单图和 Mac 原生客户端。Max/Turbo、首尾帧、视频/音频参考及 Windows 仍沿用此前受控合同测试边界，没有扩写为真实付费验证通过。代码/权限/异常路径测试及安装记录见[接入修复报告](PREDICTIONS-H3_20261021.md)。
