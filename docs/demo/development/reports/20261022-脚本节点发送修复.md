# 脚本节点发送修复

## 问题与原因

用户在自由画布脚本节点中输入剧情后无法提交。原生界面读取确认该画布只有一个脚本节点，输入已保存，没有项目画风节点。

1. 发送前的上下文解析强制要求项目画风节点；自由画布的普通剧情拆镜也因此在请求前被阻止。
2. 富文本编辑器内部处理 Enter 后直接返回，脚本节点外层的 `onKeyDown` 无法收到快捷键，导致 `⌘/Ctrl + Enter` 不触发提交。
3. 画布拆镜只提交用户剧情，缺少现有解析器需要的分镜 JSON 输出契约；选择的镜头数量、单镜时长、画风与角色版本也需要进入模型实际读取的提示词。

## 修复

- 自由画布可以没有画风节点；已经明确设置的画风必须完整，关联项目角色卡仍校验版本，不虚构默认画风。
- 使用富文本编辑器的 `onSubmit` 与 `sendOnEnter=false`，普通回车换行，`⌘/Ctrl + Enter` 提交。
- 给发送按钮补充「生成分镜」名称和快捷键说明。
- 提示词复用现有分镜行 JSON 输出契约，并携带所选镜头数量、时长、已设置画风和当前角色版本；任务顶层及 input 使用同一份提示词。

## 验证

- 20 项针对性测试通过：上下文与画风可选性、角色版本校验、输出格式及数量/时长要求、提交确认/取消/并发修改保护、结果解析与脚本入口。
- TypeScript 检查通过。
- 隔离 UI 使用真实脚本组件和真实 `useCanvasStoryboard` Hook，只把任务提交与等待接口换为内存模拟；没有真实 API Key，没有调用模型。
- 无画风节点时，点击发送并确认可提交一次模拟任务，返回结果填入分镜表，节点恢复成功状态。
- 普通 Enter 只增加换行，模拟请求数不变；`⌘ + Enter` 触发第二次提交并正常回填。
- 本地发布门禁、前端生产构建、Wails 构建、内置媒体运行时检查与应用签名检查通过；按既有更新脚本原位更新 YUNTV。
- 更新后重新打开用户原画布，原剧情、三行空白分镜、文本模型选择均保留，「生成分镜」按钮与快捷键说明已出现在原生界面。

本次真实模型发送点击被自动审批拦截，理由是可能产生外部模型调用费用。因此上述结果不能视为真实 DeepSeek 输出验收。
