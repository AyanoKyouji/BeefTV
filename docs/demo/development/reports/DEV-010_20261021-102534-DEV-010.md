## 发现与修复

`make dev` 启动了正式 Go server，并将 `/api` 代理给它，但资源存储判定只识别 Wails 协议或直接访问 Go 的绝对 API 地址。开发入口的相对 `/api` 被当作纯浏览器模式，素材库只读 IndexedDB。在全新浏览器中，SQLite 已登记的真实图片仍能在画布显示，素材库却显示 0 项；本项实际复现了这个问题。

开发启动器现在显式设置非敏感标记 `VITE_BEEFTV_DEV_LOCAL_BACKEND=true`，共享资源存储判定仅在 Vite 开发模式下使用该标记，将素材读写交给现有 Go 资源库。没有增加另一套素材系统，也没有改变 API 权限、所有权、revision 或 Wails 判定。生产构建忽略该开发标记；单独启动 Vite、没有该标记时仍保留纯浏览器 IndexedDB 路径。已有纯浏览器私有素材不自动迁移。

更新后已运行的开发实例需要执行一次 `make restart`。日常启动说明已同步。

## 离线冷启动

修复后的正常开发入口先用全新浏览器采集 revision 89 基准，再完全停止原启动器、Go、Vite 和 Go 管理的 Agent，确认旧进程与 3004/8084 端口退出。随后以新进程运行同一正式 Go server、Vite 和 Go 管理的 Node 宿主。

离线使用 macOS 进程网络沙箱：拒绝所有外部出站连接，只允许 localhost。Go/Vite 及其子进程继承该规则；全新 Chrome 也在同一规则下启动。运行时侧和浏览器侧分别探测公网连接，均取得操作系统权限拒绝。浏览器同时阻止外部资源以及新增 task/chat POST；没有关闭系统网络或影响其他应用。

新浏览器不带上一轮 IndexedDB、Cookie 或内存状态，HTTP 缓存关闭。恢复后完整节点及连线与基准一致，Asset 文档一致；画布图片、素材库缩略图和素材详情原图均实际解码成功，三处字节 SHA-256 与磁盘文件一致，资源接口 HTTP 200。素材库实际显示已有的两张图片，不再显示空库。截图在抽屉展开动画结束后采集。

SQLite 仍为 5 个任务、5 条历史 API 调用记录、2 个 Resource、2 个 Asset 和 2 个版本，数量与副本创建时一致。文本调用账本与 DEV-009 原数据逐字节一致：**本轮新增文本调用 0，图片调用 0**，没有重复登记。
