# 分镜素材重新生成

## 问题与处理

脚本镜头卡片在图片或视频完成后隐藏生成按钮，提交入口也按“补齐未完成项”过滤已有成品。因此仅恢复按钮不能真正重新生成。

- 画布脚本卡片及展开分镜板的卡片均保留「重新生成图片」「重新生成视频」；视频预览继续保留。
- 按镜头显式重新生成时，图片、直接生成视频、首帧生成视频均可提交已有成品对应的镜头。工具栏批量补齐保持原语义，跳过已完成项。
- 沿用生成确认，展示模型、数量及再次计费提示。取消确认不新建节点、不改镜头关联、不入队。
- 新任务使用独立的空目标节点，保留原素材、任务及连接；关联当前镜头到新目标，避免旧成功状态或旧任务编号让批次误判新任务已完成。继承生成参数，清除旧媒体、任务回执及图片批次归属；新目标避开已有节点。
- 只重做指定媒体：图片重新生成不自动提交视频，视频重新生成不自动提交成片。首帧视频使用该镜头当前关联图片。
- 运行中、排队中和提交状态待确认的目标不可再次提交。确认期间重复点击不重复弹窗；确认后重新核对镜头及可提交状态，编辑镜头需重新确认，移动画布节点不影响提交。

## 验证

- 20 项素材选择、目标隔离、卡片状态、素材关联和参考输入检查通过；另有 8 项独立 hook 流程检查通过，覆盖图片、两种视频路径、旧结果保留、新结果回填、取消、补齐跳过成品、单镜图片确认使用实际节点模型及重复确认保护。
- 4 项批次保存检查通过：保存完成前不派发任务；保存失败、取消或切换账号时不误提交。
- TypeScript 检查通过。测试使用本地模拟任务，未调用收费模型。
- Mac 发布检查、原生构建、签名与正式应用更新通过。原生深色界面实测：已有 3/3 分镜图的脚本节点和展开分镜板均显示「重新生成图片」；点击后弹出单任务确认，模型为节点实际选择的 flux-3-image，取消后立即恢复画布，图片仍为 3/3，镜头内容及顺序保留。
- 原生验收发现确认弹窗取消后退出动画可能残留遮罩；仅对该生成确认停用进出场动画，最终客户端复验不再残留。未点击「确认生成」，未新建真实任务或媒体节点。
- 已完成视频的按钮及两种视频重新生成提交路径通过组件和 hook 检查；本次原生使用的项目暂无镜头视频，未补做真实视频重新生成。浅色及 Windows 留待平台回归。

## 卡片操作简化

按后续反馈移除成品镜头卡片末尾的「查看视频」按钮，避免多出一行重复操作。保留图片/视频重新生成及整条镜头选择；视频继续从所选镜头详情的当前视频预览区播放。

6 项既有卡片检查、Mac 发布检查及原生构建通过，已更新本机客户端。原生实测：图片及视频均完成的第一镜卡片只显示两种重新生成操作；选中第一镜后从右侧视频预览打开播放器，播放控件出现，关闭后回到原镜头详情。本轮未生成新任务或修改镜头内容。日志为 `.local/storyboard-remove-view-video-tests-20261023.log`、`.local/storyboard-remove-view-video-build-20261023.log`，截图为 `.local/storyboard-remove-view-video-20261023/card.png`。
