## 实现核对（无需修复）

### 后端原子裁决

`canvas.Service.upsertUserCanvasProjectWithAssets`（`backend/internal/canvas/user_data.go:137`）在唯一存储锁内按既有 `revision` 做原子比对：

- 新画布 `revision != 0` → 拒绝；
- 已有画布 `project.Revision != existing.Revision` → `canvasRevisionConflict()`，返回 HTTP 409 `"云端画布已有更新，已停止覆盖；请保留本地草稿并加载最新版本"`。

Agent 写路径（`canvas.node.update`、`canvas.nodes.create`、`canvas.edge.create`、`canvas.script.row.*`、`canvas.document.commit`、`canvas.task.bind`）都经由 `saveCanvasDocWithRevision` → `UpsertUserCanvasProject`；`requireExpectedRevision` 强制写操作必须带上读取时的 `expectedRevision`。所有写入共用同一个原子谓词，不存在旁路。

### 冲突错误映射

`operations/decode.go:108` 将 HTTP 409 统一映射为 `Conflict("stale_revision", …)`；`app/canvas_bridge.go:671` 将 `conversation.ReasonStaleRevision/ReasonConflict` 也映射到同一 reason。Agent 工具回执能拿到机器可读的 `stale_revision` 错误，不会误报成功。

### 前端冲突处理

`services/canvas-revision-conflict.ts` 检测到 `stale_revision` 后：

1. 调用 `preserveCanvasSyncDraft` 保留本地内容为草稿（不清空、不覆盖）；
2. `pauseCanvasBackendSubmit` 暂停自动提交，避免后台覆盖远端；
3. 用户在画布看到冲突提示，可显式选择以本地或远端为准；冲突随本地 revision 前进自动解除。

DEV-005 的 T05 场景已经以真实 `deepseek-flash` 覆盖了本项验收的核心闭环，结果如下（摘自 [DEV-005 报告](DEV-005_20261020-171515-DEV-005.md) 第 2 节）：
