## 验收条件（T502 原文）

- 允许：已有任务查询、下载重试、资源登记和交付恢复的必要修复。
- 禁止：在不核实供应商状态时无条件重新付费生成、重复登记或串错目标。
- 验收：在隔离环境中让供应商成功后的下载/落盘/登记环节失败；状态如实显示。能够恢复的窗口复用原任务和结果完成交付；结果过期等无法恢复情况明确报告，不默默重生成；重复触发恢复不产生错误重复产物。
- 交付：故障注入点、原供应商任务标识、恢复前后状态、请求次数与产物关联。支持窗口按实测说明，不承诺任何异常都可无损恢复。

## 交付管线与恢复机制

### 后端

1. 供应商成功 → `DeliverSucceededTask(task)` → `taskdelivery.Deliverer.Deliver(task)` 下载 / 落盘 / 登记 Asset。
2. 交付中断或部分失败 → `taskdelivery.Incomplete` 记录保留原 Task ID / result / stage / materializationErrorCode，不会伪造成功。
3. `startGenerationDeliveryRecovery` 后台循环每 5 秒调用 `RecoverIncompleteGenerationDeliveries(0)`，按 identity 幂等补齐下载、登记和画布绑定。
4. 失败终态被 `persistedFailureBlocksRetry` 识别，不会被恢复循环当作可重试项重新提交给供应商。
5. 超出物化预算或下载暂停/超时的任务由前端主动区分（`delivery_paused` / `delivery_timed_out`），保留"继续取回"入口。

### 前端

- `use-canvas-resource-handoff.ts` 的 `reloadCanvasNodeResource`：**继续取回只查询 / 重试原任务**；只有 stage 为 `delivery_paused` / `delivery_timed_out` 时才调用 `retryGenerationTask`（重试下载，不重新生成）。非成功任务直接报错，不会创建新的生成任务。
- `canvas-generation-consumer.ts`：物化循环有 `GENERATION_MATERIALIZATION_BUDGET_MS` 预算；`delivery_paused` → "已停止取回，可继续取回原结果"；`delivery_timed_out` → "结果取回超时，可继续取回原结果"；`result_target_unavailable` 置 `resourceReloadAvailable=false`，不再提供恢复按钮（结果过期或目标不可恢复）。
- `canvas-generation-failure.ts` 区分 `resourceReloadAvailable`（可恢复）与不可恢复错误，失败状态如实写入节点 metadata。

## 禁止项核对

- **不核实供应商状态时无条件重新付费生成**：恢复循环只对已有 `Incomplete` 记录补齐下载/登记；`retryGenerationTask` 只作用于 `delivery_paused/timed_out` 的已成功任务；`persistedFailureBlocksRetry` 阻止失败终态重放。没有重新提交给供应商的路径。
- **重复登记**：`TestIngestExistingResourceReuse` + `TestGenerationDeliveryMultipleOutputsAndNoDuplicatePersist` + `TestGenerationDeliveryConcurrentFailedRetryKeepsOneResource` 三层幂等。
- **串错目标**：`TestIngestConcurrentIdentitiesStayIsolated` + `TestGenerationDeliveryRejectsForeignStableAssetID`。
