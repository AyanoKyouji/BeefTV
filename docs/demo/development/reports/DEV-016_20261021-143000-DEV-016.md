## 三个退出时点的覆盖

### 1. 已确认保存后退出

**实现**：画布文档在 Go SQLite 持久化（`canvas_projects` / `canvas_snapshots`），资源在 `resources` / `assets` / `asset_representations` 表。SQLite WAL 保证事务边界；重启后按 revision 读取完整文档。

**集成测试**：`TestGenerationDeliverySurvivesSQLiteReopenAndUIClose`（PASS）
- 建 Task + 交付（重复两次验证幂等）→ `closeDB(t, db)` 模拟进程退出 → `open()` 重开
- 断言：`ResultStateReady`、1 个 output、`MaterializedAssetID` / `ResourceID` / `TargetBinding.NodeID` / `EffectKey` 全部正确；Asset / AssetRepresentation / Result 各 1 条（无重复）；列表接口返回一致。

**真实场景**（复用 DEV-012 冷启动验证）：
- 三画布（手动有目标 / Agent 有目标 / 手动无目标）各自 revision 7 / 6 / 5；
- 重启后 Task ID、Asset ID、storageKey、Row `imageNodeId`、`storyboard-output` 连线、文件 SHA-256 全部一致。

### 2. 生成执行中退出

**实现**：Task 状态（queued / running / failed / succeeded）持久化在 SQLite `tasks` 表。供应商调用是独立 HTTP 请求，进程退出不取消上游任务。重启后 `startGenerationDeliveryRecovery` 循环每 5 秒扫描 `Incomplete` 交付；已成功的上游结果按原 Task ID 幂等补齐下载、登记、绑定。

**集成测试**：`TestGenerationDeliveryRestartRecoversWithoutGetOrList`（PASS）；`TestIngestSameIdentityRecoversAcrossRestart`（PASS）
- 同 identity 跨重启恢复，不需要额外触发查询。

**状态可见**：前端根据 `task.stage` 与 `metadata.generationSubmissionState` 显示：
- `delivery_paused` / `delivery_timed_out` → "已停止取回，可继续取回原结果" / "结果取回超时，可继续取回原结果"，提供"继续取回"按钮；
- `submission_unknown` → "提交结果待确认，请查询原任务"（不自动重发）。

### 3. 交付过程中退出

**实现**：交付产物按 identity 幂等登记。`taskdelivery.Ingest` 层已有 `TestIngestExistingResourceReuse`（PASS）和 `TestGenerationDeliveryMultipleOutputsAndNoDuplicatePersist`（PASS）：已有资源直接复用，不重复登记；多输出各占一条记录。`TestGenerationDeliveryConcurrentFailedRetryKeepsOneResource`（PASS）：并发重试只保留一个资源。

**运行中任务恢复边界**：按 T502 要求"不承诺所有供应商运行中任务都能恢复"。本轮验证的是本地交付管线能从任何中断点幂等恢复；供应商侧（如异步视频任务）能否续跑由各供应商契约决定，报告不统一承诺。

## 断网编辑与保存

**实现**：已有项目的画布文档、素材、资源都在本地 Go SQLite / 磁盘。前端读取走本地 API，保存也走本地 API；只有模型调用依赖远程服务。

**真实场景**（复用 DEV-010 进程级断网冷启动验证）：
- 仅允许 localhost 的进程环境下冷启动；
- 已有项目完整节点、连线、素材库、原图哈希一致；
- 可读取、可编辑、可保存（本地 SQLite 写入成功，revision 前进）；
- 远程模型不可用时反馈明确（助手不可用提示、任务提交未知状态等）。

**失败反馈**（复用 DEV-005 T03 + DEV-008）：
- 保存返回 503 → 界面明确"未发送"，聊天请求 +0，本地草稿保留；
- 助手 API 不可用 → 手动提交仍可用；
- 本地接口校验失败 → 明确分类，不误报提交未知。
