## 验收条件（T502 原文）

- 允许：现有来源版本、模型配置及内容快照检查和提示的局部修复。

## 快照校验机制

### 来源版本 + 模型配置 revision

`canvas-assistant-proposal-snapshot.ts` `prepareAssistantProposalSnapshot`：

- `canvasRevision != expected.canvasRevision` → `AssistantProposalBlockedError("canvas_changed")`；
- `modelConfigRevision != expected.modelConfigRevision` → `AssistantProposalBlockedError("settings_changed")`；
- 内容 canonicalize hash 不匹配 → `content_mismatch`；
- 读写之间再校验一次，覆盖读写窗口内的并发修改；
- 提案 `source` 字段缺失或非法 → `invalid_source`。

### 后端 turn 有效性

`handler/agent_proxy.go` `/assistant/turns/:turnId/proposals/:proposalId/run`：

- 调用 `CheckAssistantProposalRunnable` 校验 turn 未撤销、未删除；
- `turn_undone` → 409；`turn_not_found` → 404；
- 前端 `confirmAssistantProposalRunnable` 把这些 reason 映射为用户可读提示，不提交任何生成。

### 执行入口协调

`canvas-assistant-proposal-execution.ts` `executeAssistantProposal`：

1. 已提交/正在提交的 proposalId 去重（连点合并）；
2. 目标节点仍存在的快速检查；
3. `confirmRunnable()`（后端 turn 检查）→ 拒绝文案直接返回；
4. `prepare()`（前端快照校验）→ 抛出 `AssistantProposalBlockedError` 提示用户；
5. 仍持有时 `buildConfirmedGenerationConfig` 校验模型未被改动；
6. 只有全部通过后才调用 `generate(nodeId, kind, prompt)`。

用户可见文案（`ASSISTANT_PROPOSAL_BLOCKED_TEXT`）：

| 场景 | 文案 |
|------|------|
| canvas_changed | 画布在提出方案后改过。请让助手重新提出方案。 |
| settings_changed | 生成设置在提出方案后改过。请让助手重新提出方案。 |
| content_mismatch | 画布显示的内容和已保存的不一致。请重新打开这个画布，再让助手重新提出方案。 |
| settings_unsaved | 生成设置还没保存。保存后再点生成。 |
| canvas_saving | 画布还在保存。稍等几秒再点生成。 |
| invalid_source | 这项方案缺少核对信息。请让助手重新提出方案。 |
| turn_undone | 这一轮已撤销，不会生成。 |
| turn_not_found | 找不到这一轮对话，未提交生成。请让助手重新提出方案。 |

## 前端专项测试

`web/test/canvas-assistant-proposal-snapshot.test.ts`、`canvas-assistant-proposal-execution.test.ts`、`canvas-assistant-proposal-source.test.ts`：**58 PASS / 0 FAIL**。

关键拒绝场景（均有受控测试）：

- 提示词未持久化就点生成 → F02 拒绝，0 任务提交
- 引用资源/远程 URL 改变 → F02 拒绝
- 画布 revision 已前进（编辑器或服务端）→ `canvas_changed`
- 全局生成参数改变（模型未变）→ `settings_changed`
- 设置还在保存 → `settings_unsaved`
- 画布保存迟迟不落 → `canvas_saving`
- 编辑器在不同画布 → `canvas_changed`
- 服务端读时用户又改 → `canvas_changed` / `settings_changed`
- 编辑器展示节点服务端已删 → `content_mismatch`
- 畸形或缺失 source → `invalid_source`
- 老历史伪造当前 baseline → 拒绝
- Durable 读失败时本地兜底 → 拒绝

正常路径：正常新鲜加载通过；待保存 settle 内继续确认；确认后后续编辑不影响已确认 inputs。

## 禁止项核对

- **继续提交已知过期输入**：前端快照校验在任何参数过期时抛出 `AssistantProposalBlockedError`，`generate` 不会被调用。
- **自动为过期提案追加付费调用**：后端 `CheckAssistantProposalRunnable` 在 turn 无效时拒绝；前端只在校验全部通过后调用 `generate`，不存在静默重试路径。
- **不静默执行旧参数**：所有拒绝都有明确用户文案，告知需要让助手重新提案。
