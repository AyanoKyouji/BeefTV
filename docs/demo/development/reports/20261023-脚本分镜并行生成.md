# 脚本分镜并行生成

## 问题

脚本节点和展开分镜板用「任意批次仍在执行」禁用了整块脚本的生成操作；镜头卡片在图片或视频运行时，只显示一个取消按钮并隐藏两类生成入口。提交锁也按整个脚本的图片/视频类型共用，快速点击不同镜头时可能合并掉后一次请求。

## 改动

- 生成限制缩小到同一目标：不同镜头的图片、不同镜头的视频，以及独立的图片和直接视频任务可连续提交。
- 每张卡片分别展示图片、视频的状态和操作。运行中的任务有各自的「取消图片」「取消视频」入口；本地等待项展示等待状态，避免重复提交。
- 批量按钮只提交仍可生成的目标，跳过已有结果、等待/运行或提交状态待确认的目标。
- 首帧视频仍要求该镜头已有可用图片；批量按钮只选择满足依赖的镜头，其他镜头的生成不阻塞它。
- 按所选镜头集合区分短暂的提交锁；同一镜头在不同视频模式间仍共用同一提交目标保护。
- 图片和视频进度分别从所有批次中查找当前绑定的目标，不再只读取最近一个批次。
- 入队同步更新引用，防止 React 尚未渲染时后一次点击丢失前一个批次或重复占用同一目标。
- 历史记录清理保留等待或运行中的批次。保存期间新加入的目标等到下一次完整保存后才提交。
- 队列仍按现有任务并发额度调度，未增加上游并发额度；超过额度继续在本地等待。普通生成未增加确认弹窗。
