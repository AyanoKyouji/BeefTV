## 1. 输入与前置条件

读取 DEV-001 实际报告、适用仓库规则和 T504 验收计划。确认当前源码位置、版本和工作区变化；若与报告不同，先记录差异和影响，保留已有修改。

以仓库真实清单、锁文件和已确认入口为依据准备工具与依赖。用户尚未提供实际工程运行结果，本任务不能沿用历史“通过”假设。初期无需真实 DeepSeek/Seedream 调用，也无需 API Key。

## 2. 允许与禁止范围

允许按既有机制准备必要依赖，启动 React、Go、Node Agent 宿主，验证 SQLite、项目和画布。允许局部修复阻碍基础启动或项目持久化的配置、接线及代码，执行必要的相关验证。

不整体升级技术栈、不替换框架或包管理器、不重建存储层、不改真实用户项目、不取消业务校验或 revision。不得为规避失败而绕过 Node 宿主或将仅浏览器运行称为完整桌面运行。

使用应用支持的隔离数据路径或已有测试方式；先确定实际支持方式，不通过随意重设 HOME、清空数据库或迁移真实数据实现隔离。若缺少安全可用的测试隔离方式，记录影响并先定位解决方法，不直接操作真实项目。

## 3. 执行步骤

1. 核对 DEV-001 的工具/命令建议，再读取真实脚本和必要初始化步骤。按锁文件和现有项目方式安装依赖，不无理由更新版本或重写锁文件。
2. 确定隔离测试项目和数据/资源目录，记录本机运行平台、实际命令及日志位置。
3. 按现有入口构建/启动核心组件，分别确认前端可用、Go 业务可访问、SQLite 可读写、Node Agent 宿主可启动及就绪。没有 LLM 凭证时不要求工具调用成功，但不能仅以聊天面板显示证明宿主就绪。
4. 新建项目，进入画布，创建两个测试文本对象和 Script 中的三个分镜；记录项目/分镜 ID、内容及归属。
5. 验证基础选择、移动、编辑、删除、画布平移和缩放；删除使用测试副本，保存恢复场景保留三个分镜。
6. 修改第二个分镜，调整布局，等待现有机制明确确认保存，记录已保存内容/版本。
7. 彻底退出测试应用和其当前会话，再重新启动、打开该项目；核对名称、三分镜内容、用户修改、布局及 ID。不能只刷新页面或切换项目代替冷启动。
8. 失败时定位实际环节，必要局部修复后重跑受影响场景；记录失败尝试、改动和恢复结果，不为留下改动强行编码。
