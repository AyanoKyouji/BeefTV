# Demo 演示操作指南

本项为阶段六的演示准备，未宣布阶段六或最终平台验收完成。建议以 6～8 分钟的已有成果展示为主，现场真实调用单独安排。本轮整理没有模型调用。

## 1. 开场与材料

开场说明：“这个 Demo 验证 AI 与人围绕同一份分镜协作：人能修改，Agent 能读取最新内容，生成前需要确认，结果能与镜头关联并在本地恢复。”

原开发机已准备离线成果包：`.local/demo-materials-20261021-180942/presentation/index.html`。双击打开即可，包含四张历史真实图片、一张导入色卡、三张历史界面截图，以及来源/版本/文件哈希清单。无需启动应用或联网；包内未放数据库、模型配置和日志。此目录被 Git 忽略，新检出仓库不会自动拥有媒体包。

同目录外的 `presentation.zip` 可用于传送静态材料；解压后打开 `index.html`。不要把整个 `.local` 或开发数据目录当作分享包。

副本仅复制业务 SQLite 和资源文件，已核对 SQLite 完整性、业务计数和资源哈希。没有复制模型配置、令牌、密钥文件或 Agent 会话目录；不能期待历史聊天面板或立即真实调用。数据库仍含业务及调用记录，仅作本机私有数据，不能并入分享包。**本轮没有启动副本，应用中的新排练与进程恢复不能据此视为已通过。**

如要演示已有项目，在仓库根目录先查看并停止启动器管理的当前实例；停止会中断该实例，请先保存正在编辑的内容：

```bash
make status
make stop
BEEFTV_DEV_DATA_DIR="$PWD/.local/project-workbench-debug/demo-materials-20261021-180942-agent" make dev
```

进入对应画布，先确认三条分镜及第二镜输出；只改副本中无关备注或布局，等保存完成后退出并重开，核对改动是否恢复。不要在截图中的历史“生成”提案上重复确认。手动案例换为 `…-manual`，同样必须先 `make stop`。没有要求现场编辑时，静态包已足够完成默认讲解。

演示结束返回日常目录：

```bash
make stop
make dev
make status
```

最后应看到日常目录 `.local/project-workbench-debug/daily`。启动器只有一套状态记录；已有实例运行时设置另一个数据目录仍会打开原实例，不能省略切换前的停止。详见[本机一键启动](本机一键启动.md)。

## 4. 可选：现场真实 Agent 流程

现场请求有费用和等待时间，先确认当前渠道及实际计价；不使用 Seedream/Seedance。本次整理未替现场预先生成新结果。若安排现场生成，使用新的独立数据目录和新项目，按正式 UI 配置文本/图片渠道，凭证不进入提示词、截图和报告。创建分镜等 Agent 操作也可能多次调用文本模型，不能按一条聊天消息计一次请求。

1. 创建一个新项目，打开 Agent，指定只创建三条分镜。例如：“为一段 15 秒新能源汽车宣传片创建一个三镜头分镜脚本。先只创建分镜，不生成图片或视频。”按真实工具结果核对三个稳定行及内容，遇到操作授权先审阅。
2. 人工修改第二镜的图片提示词并确认保存。可用以下内容，增加一个便于核对的新细节后保存：

   > 白色概念汽车驶过雪山公路的弯道，右侧车身映着绿色极光，路边有一块橙色反光路牌，高空斜俯拍，真实摄影，无文字无商标，正方形构图。

3. 选中该 Script 节点，发送以下指令。不要把刚才的提示词再粘进聊天，要核对工具确实读取了最新保存的第二镜：

   > 请根据当前选中的分镜脚本的第二个镜头生成一张参考图片：先读取它最新保存的图片提示词，将原文用作新图片节点提示词，把图片节点关联到这个镜头，再提出默认图片模型的生成提案。只处理这一镜，不修改分镜内容，不生成视频，等我确认后再生成图片。

4. 查看实际读取与提案内容、目标镜头、模型及数量，核对人工修改已包含。此时还未授权生成图片。审阅通过后只确认一次，等待真实任务状态；第一、三镜不应被修改。
5. 完成后核对实际图片、第二镜正式输出关系、素材库、保存及退出恢复。方图单张配置可沿用历史已验证选择，实际尺寸以产物为准；不保证像素内容逐字满足提示词。

勾选表格行用于批量生成，不代表 Agent 隐含选中了该行；必须在指令中明示“第二个镜头”。已有绑定输出的历史项目不适合反复生成演示，应使用空输出的新项目。

如要展示手动入口，另开新项目：创建 Script 与图片节点，必要时 Shift 点击只选择图片，使用“图片设置 → 上传图片”导入色卡，或手动提交单张真实图片，再核对目标行输出关联与素材库。导入不计作 AI 生成；两条流程的请求分别计数。

## 5. 故障切换与现场记录

| 现象 | 现场处理 |
|---|---|
| 明确参数拒绝且没有上游任务 | 查看具体参数，修正后再决定是否发起新的收费请求；留原错误与新任务的对应关系 |
| 503、超时或“提交结果尚未确认” | 查看原任务状态；保留未知保护，不立即重发、不称任务已取消；切回静态成果继续讲解 |
| 页面/宿主未就绪、模型配置缺失 | 保存现有工作，展示静态材料；把故障另记，不能用已有图片冒充这次成功 |
| 图片生成耗时超出讲解预算 | 展示历史成果，清楚说明现场任务仍在等待；不要为了展示效果重复提交 |

现场记录：代码提交、运行方式、项目/画布/目标行、提案确认时刻、任务/素材/资源标识、文本 dispatch 数、真实图片 POST 数、视频数、受控请求数、错误及保存/重启结果。计价以供应商账单为准。任务状态需核对，不能仅凭画布出现图片推断请求成功。
