# 开发与跨平台验证约定

- 生效日期：2026-10-20（Asia/Shanghai）。
- 依据：用户要求后续直接在本机 Mac 开发和运行验证，仅在部分阶段功能完成后再验证 Windows。
- 适用范围：第六阶段后续开发；调整执行平台与回归频率，保留原有功能范围及最终 Windows 验收目标。

## 1. 日常开发

以 `${BEEFTV_REPO}` 为主开发工作区，在 Mac 上完成代码修改、组件检查、实际业务操作、模型接入及保存/恢复验证。每项报告记录实际平台和运行方式。

React/Go 开发联调适用于页面、数据和业务流程；涉及 Wails 绑定、窗口、文件选择、桌面资源定位或打包时，应在 Mac 原生客户端验证相关能力。既有 Mac 原生安装规则继续有效，正式本机应用路径为 `/Applications/BeefTV.app`，按仓库现有脚本更新。

DEV-002 现有证据是浏览器界面连接 Go 桌面组合根，以及独立 Node 宿主测试；尚不能据此称 Mac 原生窗口已验证。后续首次需要原生能力时补齐实际启动结果。无需每完成一个 DEV 都重新发送 Windows 源码包或要求用户在两台机器间切换。

## 2. Windows 回归时机

| 时机 | 默认检查范围 |
|---|---|
| Agent/分镜协作链完成后（W1/W2，M2 对应功能） | 随包 Node 就绪、项目/三分镜编辑、修改后读取最新内容与目标定位；补齐 DEV-003 尚缺的宿主及正常退出恢复证据 |
| 真实图片与素材交付链完成后（W3/W4，M3 对应功能） | 手动及 Agent 图片路径、实际下载落盘、分镜关联、正常退出与离线恢复 |
| 最终集成（DEV-017～019 / W6） | 同一最终 Windows x64 完整构建、运行依赖、关键异常和双路径端到端验收，仍为最终交付必要条件 |
| 中途出现平台相关改动 | 若触及 Windows 路径/编码、文件锁、SQLite/Node 进程、Wails/WebView2、随包资源或构建脚本，按影响提前做定向 Windows 回归 |

前两个功能检查点可在进度接近时合并一次，保留各自检查结果；最终 Windows 验收独立完成。检查点描述的是功能成熟时机，不要求先宣布里程碑达成再验证必要条件。
