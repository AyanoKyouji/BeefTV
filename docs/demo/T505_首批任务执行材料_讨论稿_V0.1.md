源码尚未下载，因此工程启动时先取得源码，再执行 DEV-001。此步骤是首批工程的必要准备，不新增 DEV 主编号，也不算基线检查已经通过。

- 历史选定的来源：`https://github.com/glanderness/BeefTV`。本轮只引用已确认来源，没有重新联网检查或下载。
- 建议默认目录：`${BEEFTV_REPO}`。这是未来获取源码的建议位置，当前不存在已经取得源码的结论。
- 工程启动时先检查目标是否存在；若已有源码则核对来源并复用合适工作区，保留全部既有改动；不覆盖、清理或强制重置。
- 新获取时记录实际远端、分支及 Commit；历史 T401 SHA 只是研究依据，不强制检出它。确有版本选择理由时记录理由及影响。
- 读取适用的仓库规范后再执行对应任务。网络或目录权限阻塞时报告实际条件，不用下载压缩包等方式绕过必要的审批或访问约束。

T505、T506 的计划确认不会执行此准备。进入第六阶段并开始首批工程时，才按上述步骤落地。

## 四、首批推进方式

1. 工程启动后取得/定位源码，执行 DEV-001；依真实基线判断下一步，不顺带修改业务或安装依赖。
2. DEV-001 提供可靠基线后执行 DEV-002，验证基础运行和隔离项目的编辑、保存、冷启动恢复。
3. 基础运行可用后尽早执行 DEV-003，使用现有 Windows 电脑验证完整产物和运行组件。

每张任务卡是独立执行范围，交付当前任务的报告后再按后续执行指令推进。第一批不要求配置 DeepSeek 或 Seedream 的真实调用来证明基础启动；模型验证归 DEV-004/007。Node 宿主自身可启动仍须验证，不能把未配置模型当成跳过宿主检查的理由。

所有任务保留 Wails + React + Go + SQLite + Node Agent 路线，复用既有业务层、revision、Task/Worker 和资源交付。先验证已有实现，有缺口才局部修复；每项保留可复查结果，不以编译成功代替业务通过。
