### 2.1 针对已提供资源的准备顺序

最新平台安排以用户在 2026-10-20 的要求为准：日常在 Mac 开发与运行验证，功能阶段完成后再回归 Windows；具体时机与证据口径见[开发与跨平台验证约定](development/开发与跨平台验证约定.md)。以下列表保留最初资源准备顺序，不要求反复安装环境或每个 DEV 都切到 Windows。

1. 工程启动后，先将 BeefTV 获取到明确的开发目录，再执行 DEV-001 固定实际基线；当前仍只编制计划，未下载源码。
2. 优先使用现有 Windows 电脑完成 DEV-003，安排构建产物传递、安装/运行和结果记录。无需为本次验证先建立 Windows 虚拟机。电脑存在不代表本会话已有远程操作权限或运行通道；无法直接操作时，由用户按具体步骤实测并提供结果。
3. 文本接入先确认公司中转的 Base URL、DeepSeek 模型 ID、认证及工具调用支持，再验证 Agent 业务工具；不把中转的普通聊天可用直接视为 Agent 已兼容。
4. 图片接入先确认 Seedream 是否为实际可用型号、模型 ID、请求参数、同步/异步任务及图片获取方式，再与 BeefTV 现有适配器对照。先验证手动生成，随后接通 Agent；若需局部适配，归入对应 DEV 任务，不默认要求更换模型。
5. API Key 在实际模型配置阶段通过应用设置或既有凭证机制配置；计划文档只记录服务与脱敏信息。当前不要求用户在聊天中提供密钥。

中转接口说明和实际配置的核对属于工程准备/对应模型任务。当前没有接口原文或真实请求结果，不能宣布 DeepSeek 工具调用或 Seedream 生成已通过。

## 五、每次工作会话的节奏

1. 开始时读取上次报告和当前工作区，确认主要任务、前置条件及此次可使用的环境；不重复已失效之外的全部检查。
2. 先复现或验证已有行为。已满足则记录 Verified；有真实缺口才局部修复。
3. 完成该任务的必要业务测试和受影响回归；真实付费调用遵守现有确认和额度边界，复用仍有效的证据。
4. 结束前记录当前代码/构建版本、结果、证据、未执行项、下一步。未完成工作可保持进行中，不为了凑一个会话关闭任务。

同一主要任务可跨多个工作会话。代码与可恢复记录遵守仓库规范和实际授权；不把“会话结束”解释为必须提交 Git、重置或清理工作区。

## 七、工期安排与近期节点

已确认工作日每日约 6～8 小时；该时间包含开发、排错、真实操作、测试与记录，不全部作为编码时间。实际代码基线和接口兼容性尚未验证，本轮不据此直接承诺“几天完成”。使用以下方法把相对安排转成后续日历：

| 校准点 | 依据 | 更新内容 |

| 资源信息登记（本轮已补） | 源码未下载、已有 Windows 电脑、DeepSeek/暂定 Seedream 经中转、工作日每日 6～8 小时 | 工程开始时先准备源码和基线，尽早安排实体 Windows 启动与中转接口验证 |

估算记录采用：任务/批次、预计投入范围、依据、可用时段、外部等待、完成条件、下次校准点。未取得依据的栏位保留待估，不填虚构数字。外部等待单独记录，不能直接把投入小时当作日历完工时间。

用户确认保留 2026 年 10 月 23 日（周五）的非强制展示节点。第五阶段尚未收口、工程尚未启动，不把此前日期自动算成已经投入的完整开发日；工程启动后再根据剩余可用时段校准。

首个完整工作日优先取得源码、完成 DEV-001，并推进 DEV-002 和 Windows 基础构建；这些是安排重点，完成情况仍取决于实际运行。基础启动后，优先验证 DeepSeek 工具调用，并提前核对 Seedream 中转接口，尽早暴露接入问题。每个工作日结束时按任务结果选定下一主要任务，临近展示保留整理实际构建、证据和演示步骤的时间。

临近展示前按实际证据选择内容：

- 只有基础应用与对象操作通过：展示客户端和创作交互，说明 Agent/模型尚未通过的部分。
- 真实生成、素材和恢复通过：展示基础媒体创作能力；Agent 链路未验证时明确说明。
- 完整 Windows Agent 闭环通过：展示核心协作能力，提供对应构建与连续流程证据。

节点不改变 P0 标准；必要时展示阶段性成果并继续开发。预置素材可辅助讲解，但明确标记且不计入真实生成证据。
