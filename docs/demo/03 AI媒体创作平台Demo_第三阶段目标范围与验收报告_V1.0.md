## 二、D301：核心验证目标

### 2.1 四项需要证明的能力

| 验证目标 | 可观察的证据 |
|---|---|
| Windows 应用能够承载真实 AI 创作 | 在 Windows 实际环境启动、编辑，并调用真实模型 |
| 无限画布管理真实创作内容 | 文本、分镜和图片是可编辑、可关联、可保存的对象 |
| Agent 与用户协作操作同一份内容 | Agent 创建对象后，用户修改，Agent 能读取最新状态继续工作 |
| 模型结果成为可继续使用的项目素材 | 生成结果进入项目，与分镜关联，重启应用后仍可恢复 |

### 2.2 基础闭环与核心闭环

**基础 Demo：**创建项目 → 操作无限画布 → 手动调用真实图片模型 → 管理生成素材 → 保存与恢复项目。

**核心 Demo：**在基础能力上，完成 Agent 创建分镜 → 用户手动修改 → Agent 读取最新内容 → 调用真实模型生成素材 → 结果关联画布 → 保存与恢复。

AT006 是重点差异化验证：Agent 不能只依靠聊天历史，而应读取用户修改后的当前创作对象。实现应建立在统一对象与操作机制上，不能为固定案例编写特殊判断逻辑。

### 2.3 设计边界

- 项目统一组织创作内容，画布负责呈现和操作。
- Agent 与手动编辑尽可能复用相同的平台创作能力，共享最新状态。
- 本地基础编辑不强制依赖互联网；远程模型不可用时，相应 AI 功能可不可用。
- 开放式接入不等于 Demo 必须兼容所有模型、协议和参数。
- 不将完整七阶段流程、复杂视频制作或商业系统作为核心闭环的前置条件。

## 三、D302：典型场景与双路径演示

### 3.1 核心场景：三镜头新能源汽车宣传片

本场景用于验证创作连续性，不要求以完整视频成片作为 P0 结果。

| 步骤 | 操作与预期结果 | 主要验证点 |
|---|---|---|
| 1 | 启动 Windows 客户端，创建项目并进入画布 | 客户端、项目与主要交互 |
| 2 | 向 Agent 提出三镜头新能源汽车宣传片要求 | 真实文本模型理解任务 |
| 3 | Agent 创建三个可操作的分镜对象 | 真实对象创建，不只是聊天文本 |
| 4 | 用户手动修改其中一个分镜 | 人工编辑与 Agent 产出可以衔接 |
| 5 | 要求 Agent 基于修改后的内容继续处理 | 读取最新上下文，重点验证 AT006 |
| 6 | 调用真实图片模型生成分镜素材 | 真实请求、任务反馈与结果获取 |
| 7 | 图片进入项目，与对应分镜关联并在画布展示 | 生成结果转为项目素材 |
| 8 | 保存，退出应用，再启动并打开项目 | 内容、素材、关联与布局恢复 |

条件允许时，再增加视频生成、导入、预览或基础编排。没有视频模型不阻碍 P0，但不得将导入视频描述为真实生成。

### 3.2 辅助场景：手动图片生成

用户不通过 Agent，也能创建或编辑创作对象、填写生成内容、选择可用图片模型、发起任务，并将结果保存到项目。

该路径证明 Agent 是协作者，基础创作能力可以独立使用；同时用于检查手动操作与 Agent 操作是否共享平台能力。

### 3.3 演示真实性

明确标记真实实现、部分实现、模拟演示和规划内容。预置素材可以辅助讲解或应对服务故障，但不能证明真实模型调用成功，也不能替代核心验收。

## 四、D303：功能范围与优先级

### 4.1 P0：核心验证必须具备

| 功能组 | 本次完成边界 |
|---|---|
| Windows 客户端 | 在实际 Windows 环境启动并操作主要创作界面 |
| 项目管理 | 创建、保存、重新打开项目，退出应用后可恢复 |
| 无限画布 | 文本、分镜、图片节点及基础操作，承载真实对象 |
| 真实 LLM Agent | 理解指令、创建分镜、读取当前对象并发起图片生成 |
| 文本模型 | 至少一种真实可调用的文本模型 |
| 图片生成模型 | 至少一种真实可调用的图片生成能力 |
| 任务管理 | 生成过程有可观察的状态与结果，失败能被识别 |
| 素材管理与持久化 | 结果纳入项目，与分镜建立关联，保存后可继续使用 |
| 手动创作路径 | 不依赖 Agent 完成基础编辑与图片生成 |

“任务与素材持久化”是最终范围的一部分；具体哪些运行中任务可恢复、是否续跑及重试语义由第四阶段设计，不提前承诺完整任务恢复系统。

### 4.2 P1：条件允许时增强

| 功能组 | 增强方向 |
|---|---|
| 视频 | 导入、预览及真实生成 |
| 时间线与导出 | 基础时间线、拼接与成品导出 |
| 图片处理 | 基础图片编辑 |
| Agent 扩展 | 修改节点、更复杂的多步骤执行 |
| 工作流 | 简化工作流能力 |

P0 中的 Agent 创建分镜、读取最新内容和发起图片生成，不因“多步骤执行属于 P1”而降级。P1 指更一般、更复杂的执行能力。

### 4.3 P2：本次不要求

完整七阶段自动化、完整节点执行引擎、专业多轨剪辑、完整图层与特效、多 Agent、团队协作、云同步、完整商业系统、模型自动部署与插件市场。

正式账号、支付、订阅、充值、授权及服务器管理交付不纳入本次 Demo。公司中转平台保持可选，不成为基础编辑及所有模型调用的强制依赖。

### 4.4 范围控制原则

优先保证已完成能力稳定，再增加功能。周五展示节点不改变既定核心验收要求，也不构成将大量 P1 提升为 P0 的理由。技术调研若发现不可行条件，应记录影响及方案调整，不通过删除失败标准宣称核心通过。

## 五、D304：验收标准与验证方式

### 5.1 验收原则

以实际操作、结果检查及异常测试为依据。真实模型调用、真实对象操作和退出应用后的恢复必须分别验证；界面完成或单个接口成功不能代替完整闭环。

核心流程建议连续成功两次，以排除偶然成功。Windows 必须有实际环境证据；其他操作系统运行不能代替 Windows 验收。

### 5.2 AT 编号记录

讨论采用 AT001～AT012。以下已按 T504 找回的 D304 原文补齐，沿用原编号；正文标题与原汇总短标题有详略差异时保留业务含义。

| 编号 | 已核实的验收主题 | 记录说明 |
|---|---|---|
| AT001 | Windows 客户端运行 | 需要 Windows 实机或实际 Windows 环境操作证据 |
| AT002 | 项目保存与恢复 | 保存后重新打开；结合退出、重启验证 |
| AT003 | 基础画布操作正常 | 文本与分镜创建、选择、移动、编辑、删除及画布平移缩放 |
| AT004 | 创作对象之间的关联正确 | 关联可读取、修改及持久化，不只是视觉位置关系 |
| AT005 | Agent 创建分镜 | 真实创建可操作对象 |
| AT006 | Agent 读取最新创作上下文 | 用户手动修改后，Agent 使用更新内容继续处理 |
| AT007 | Agent 交互状态反馈正确 | 原汇总称“Agent 头像状态动画”；含空闲、处理、结束、任务等待和失败反馈 |
| AT008 | 真实图片生成 | 必须有真实模型请求及生成结果 |
| AT009 | 手动生成能力不依赖 Agent | 不使用 Agent 也能真实生成图片 |
| AT010 | 生成任务状态与异常处理 | 正常、不可用、超时或未知、模型错误、重复点击及已有项目保护 |
| AT011 | 媒体素材能够复用与恢复 | 导入和生成的图片均能保存、恢复及关联，来源可区分 |
| AT012 | 基础创作不依赖互联网 | 离线启动和项目打开、素材查看、编辑、移动与保存 |

本表是编号追溯记录，不是对已通过 D304 的标准作删减。T504 已补入完整操作、DEV 对照和证据要求。下列检查要求归纳验收方向，不分配新的 AT 编号。

### 5.3 必须覆盖的检查内容

| 检查方向 | 操作及预期结果 |
|---|---|
| 画布与对象 | 创建、编辑、移动相关对象，内容与可视结果一致 |
| Agent 创建对象 | 指令产生真实分镜，用户可继续编辑，项目能保存 |
| 最新上下文 | 修改分镜内容后要求 Agent 继续生成，检查实际请求使用修改后的内容 |
| 手动路径 | 无需 Agent 也能完成基础编辑与真实图片生成 |
| 真实模型 | 文本与图片使用真实服务，生成结果与请求可以对应 |
| 任务反馈与异常 | 可以观察任务状态及失败，不能以无反馈或虚假成功掩盖失败 |
| 素材关联 | 结果进入项目，关联对应分镜，并可继续使用 |
| 保存与重启 | 退出并重启应用后，内容、素材引用、关联和布局可恢复 |
| 离线基础操作 | 断开互联网后可继续已有项目的基础编辑；远程 AI 功能边界明确 |

AT006 应检查对象实际内容与生成请求，不能只看 Agent 回复“已读取”。若 Agent 仍用旧分镜，即使客户端、图片模型和保存可用，核心协作仍未通过。

### 5.4 增强验收

视频生成作为条件性或增强项。交互切换继续作为重点增强验证，尤其关注选择对象、已有修改、关联素材与上下文是否连续。时间线、高级节点工作流不作为 P0 前置条件。

### 5.5 完成程度与结果分类

功能状态使用：**已实现、部分实现、模拟演示、规划中**。功能完成状态与验收通过状态分开记录。

| 结果 | 判断依据 |
|---|---|
| 核心验证通过 | 基础创作闭环成立，Agent 与用户共同操作真实内容，最新上下文及关键验收得到真实验证 |
| 基础媒体创作可用 | 客户端、画布、真实生成和保存等已验证，但 Agent 协作或最新上下文尚未充分验证 |
| 仅交互原型 | 能展示界面与流程，但模型、Agent 或可靠保存仍依赖模拟或未打通 |

三类均可作为内部展示成果，但必须说明实际完成度。只有基础媒体生成可用时，不能宣称 P008、P009 的核心协作设计已充分验证。

## 七、风险登记与应对

| 编号 | 风险 | 优先级 | 应对原则 |
|---|---|---|---|
| R301 | 时间与功能范围不匹配 | 高 | 区分近期展示与完整 Demo；优先稳定 P0 |
| R302 | BeefTV 不适合既定需求 | 高 | 检查真实代码、扩展成本、Windows 运行方式与许可证；必要时比较替代路径 |
| R303 | 缺少真实模型资源 | 高 | 先确保一种文本模型与一种图片模型可用；模拟不能替代验收 |
| R304 | Agent 与画布数据不一致 | 极高 | 优先明确真实状态归属、统一对象和操作机制，不能留到后期 |
| R305 | 项目与素材无法可靠恢复 | 高 | 保存恢复作为基础能力，避免临时链接失效及外部源文件丢失 |
| R306 | AI 开发造成结构失控 | 高 | 小步任务、保持数据与接口一致、变更后回归关键能力 |
| R307 | 混合交互复杂度失控 | 中高 | P0 聚焦画布与 Agent，其他编辑器逐步扩展 |
| R308 | 服务或环境影响演示 | 中高 | 预查运行条件及模型耗时；备用素材明确标记为预置或模拟 |

风险等级是规划阶段初步判断，不表示问题已发生。第四阶段优先处理 **R302、R303、R304**。

继续保留 **T001：不同创作交互方式之间的数据关联与交互一致性**。新增编辑器时，需验证它能否与已有画布共享创作内容，不能只检查独立界面能否运行。

## 八、近期展示策略与 AI 开发约束

### 8.1 周五阶段性展示

| 成熟度 | 展示内容 | 能说明什么 |
|---|---|---|
| 第一层 | Windows 形态、画布、基础对象和项目交互 | 产品交互方向 |
| 第二层 | 加入真实模型、素材管理与分镜到图片链路 | 实际媒体创作能力 |
| 第三层 | Agent 创建分镜、读取手动修改并生成素材 | 核心协作设计 |

这是展示成熟度划分，不替代 D303 功能清单，也不提前承诺周五全部 P0 完成。真实运行是主要证据；预先准备的素材仅用于补充说明。

### 8.2 AI 辅助开发约束

1. 先明确关键对象、接口与模块职责，再逐步实现。
2. 每次围绕明确功能目标开发，避免一次要求 AI 改动大量无关模块。
3. 对关键数据与操作机制保持一致，避免重复状态、重复接口和临时补丁积累。
4. 变更后按验收编号回归相关能力，在真实环境确认结果。
5. AI 负责辅助实现与排错，开发者负责判断需求、审查关键设计和确认集成结果。
