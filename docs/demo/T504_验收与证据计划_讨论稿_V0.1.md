## 八、证据包和记录模板

工程开始后建议在任务材料目录下建立 `evidence/<run-id>/`，实际根目录由 DEV-001/T505 确定，当前不创建空证据或假日志。一个运行可支持多个 AT，主表引用同一证据，避免复制和重复调用。

每次运行最少记录：

| 字段 | 内容 |
|---|---|
| 身份与时间 | Run ID、执行时间及 Asia/Shanghai 时区、执行者/操作设备、AT/DEV/E2E 编号 |
| 版本与环境 | Commit、未提交差异引用（如有）、构建产物标识、Windows 系统/架构、必要依赖 |
| 模型配置 | 中转服务标识、协议、实际 DeepSeek/图片模型 ID、必要参数及配置版本，不含密钥 |
| 业务对照 | Project/Script/Row ID、编辑前后内容与 revision、提案/Task/供应商请求 ID（若有）、Asset/文件引用 |
| 操作和结果 | 前置条件、步骤、预期、实际、状态、失败原因和限制 |
| 证据与复现 | 截图/短视频、脱敏工具或任务记录、文件/资源对照、下一次复现方式 |

关键证明链为：用户编辑 → 后端提交确认 → 工具读取 → 提案/实际生成参数 → 真实请求/任务 → 图片落盘 → 分镜业务关联 → 冷启动恢复。既有日志、任务记录及测试输出能证明时直接复用；缺少关键环节时只补必要的可观测性，不建立大型日志系统。

截图证明可见结果，业务记录证明对象身份与参数，文件检查证明实际落盘；单独一张完成截图不足以关闭整条链。Windows 电脑由用户操作时，注明执行者和设备，保存用户提供的实际步骤与证据；仅口头称“没问题”不足以关闭具体检查。

建议的逐项记录格式（空白模板，不代表已执行）：

```text
Run ID / AT 编号 / 对应 DEV：
代码与构建标识 / 系统与模型配置引用：
前置条件及执行方式：
步骤、预期结果：
实际结果：
验收状态：NOT TESTED（执行后据证据更新）
证据路径 / 对象与任务对照：
失败、未执行项、限制及下一步：
```

API Key、认证头、访问令牌和敏感下载链接不进入报告或录屏。必要参数保留可核查的测试语义及身份，不因脱敏把证明最新输入所需的信息全部删掉。
